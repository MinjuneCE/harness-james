# 코드 컨벤션

어느 프로젝트에도 속하지 않는 코드 규칙이다. 프로젝트 이름, 고객사 이름, 프로젝트의 업무 용어는 이 폴더의 문서에 쓰지 않는다.

## 층

| 문서 | 적용 대상 | 규칙 번호 |
|---|---|---|
| `common.md` | 모든 코드 | S, V, T, K, C, X |
| `be/common.md` | 서버 코드 | B |
| `fe/common.md` | 화면을 그리는 코드 | F |

- 규칙은 "무엇에 기대어 참인가"로 층을 정한다. 어디서나 참이면 `common`, 서버 코드라서 참이면 `be/common`, 화면 코드라서 참이면 `fe/common`, 특정 언어나 프레임워크라서 참이면 그 스택 문서에 둔다.
- 규칙은 참인 층 가운데 가장 위에 한 번만 적는다. 아래 층은 위 규칙이 그 스택에서 어떤 모양인지만 적는다. 그때 위 규칙의 번호를 괄호로 단다.
- 아래 층은 위 층의 규칙을 뒤집지 않는다.
- 스택 문서는 프로젝트가 쓴다. 이 폴더에는 본보기만 `examples/`에 둔다(Java·Spring 서버 하나, UI 확장 화면 하나). 본보기는 규칙이 아니고 자동으로 읽히지 않는다.
- 요약본은 `rules/conventions-*.md`다(공통, 서버, 화면). 설치하면 `~/.claude/rules/`에 놓이고, 파일 경로로 걸려 있어서 해당 파일을 읽거나 고칠 때 자동으로 로드된다. 이 폴더의 문서를 고치면 요약본도 같이 고친다.

## 프로젝트가 적는 것

프로젝트는 컨벤션을 적용하는 쪽이다. 아래는 프로젝트 작업 공간의 문서에 적고, 이 폴더에는 넣지 않는다.

- 어느 층을 쓰는지
- 스택 문서와 그 요약(`examples/README.md`의 쓰는 법과 켜는 법)
- 폴더·패키지 이름과 계층 방향(S1)
- 규칙이 프로젝트 선택으로 남긴 것(스택 문서의 "프로젝트가 정하는 것")
- 없으면 안 되는 설정 키와 없어도 되는 설정 키(V1)
- 테스트 도구, 테스트 파일 위치, 실행 명령, 외부 시스템으로 보는 범위(T5)
- 자동 검사 도구와 실행 명령, 기준선 위치
- 기본 코드와 우리 코드가 섞인 저장소라면 우리가 쓴 파일의 범위
- 규칙의 예외. 어느 규칙의 예외인지 번호와 이유를 함께 적는다
