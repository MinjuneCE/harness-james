# 예시: 스택 문서

언어와 프레임워크에 기대는 규칙은 프로젝트마다 다르다. 그래서 이 컨벤션은 스택 규칙을 정하지 않고, 프로젝트가 자기 스택 문서를 쓸 때 볼 본보기 두 개만 둔다. 설치해도 이 폴더의 요약은 `rules/`에 들어가지 않고, 어떤 파일을 열어도 읽히지 않는다.

| 예시 | 보여 주는 것 |
|---|---|
| `be/java-spring.md`, `rules/conventions-java-spring.md` | 서버 스택 문서. 위 층 규칙(S·V·T·B)이 이 스택에서 어떤 모양인지, 자동 검사 표, "직접 쓰지 않는 것", "프로젝트가 정하는 것" |
| `fe/shopify-ui-extension.md`, `rules/conventions-shopify-ui-extension.md` | 화면 스택 문서. 폴더 구조와 의존 방향, 설정·번역 파일 짝 테스트, 감싼 한곳에서만 쓰는 기능 |

## 스택 문서를 쓰는 법

- 문서는 위 층(`common.md`, `be/common.md`, `fe/common.md`)이 그 스택에서 어떤 모양인지만 적는다. 위 규칙의 번호를 괄호로 달고, 위 규칙을 뒤집지 않는다.
- 요약은 `paths:`로 그 스택의 파일에만 걸고, 위 층 요약에 이미 있는 줄은 되풀이하지 않는다.
- 근거는 그 프로젝트의 코드다. 근거가 없는 규칙은 적지 않는다.

## 프로젝트에서 켜는 법

1. 예시를 그대로 쓰거나 고쳐서 프로젝트 작업 공간의 문서 자리에 둔다.
2. 요약을 그 프로젝트의 `.claude/rules/`에 둔다. 그 뒤로 프로젝트의 해당 파일을 읽거나 고칠 때 공통·서버·화면 요약과 함께 읽힌다. 모든 프로젝트에 걸려면 설정 폴더의 `rules/`에 둔다.
   - 여럿이 쓰는 저장소라면 `.claude/rules/`가 커밋 대상이 된다. 개인 규칙을 그 저장소에 넣지 않으려면 git 제외 목록(`.git/info/exclude`)에 넣거나 설정 폴더의 `rules/`에 둔다.
3. 요약 안의 전체 문서 경로를 1에서 둔 자리로 고친다.
