# Shopify UI 확장 규칙

> 예시다. 프로젝트가 자기 스택 문서를 어떻게 쓰는지 보여 주는 본보기로, 설치해도 자동으로 읽히지 않는다. 켜는 방법은 `examples/README.md`에 있다.

Shopify UI 확장(고객 계정, 체크아웃. Preact와 JS)에 적용한다. `common.md`와 `fe/common.md`가 먼저다. 괄호 안 번호는 이 규칙이 구체화하는 위 층의 규칙이다.

## 1. 구조

```
extensions/<확장>/
├── src/
│   ├── <진입점>.jsx   확장 target마다 하나. 그리기만 한다
│   ├── components/    그리는 코드
│   ├── hooks/         화면 흐름
│   ├── services/      서버 호출과 제출 흐름
│   ├── utils/         순수 판단
│   └── config/        상수
├── locales/           번역 파일
└── test/              순수 함수와 서비스의 테스트
```

- **E1. 의존은 진입점·components·hooks → services → utils → config 방향으로만 간다(S1).** utils와 config는 services나 jsx를 import하지 않는다.
- **E2. 분기 로직은 jsx와 hook 밖의 utils에 둔다(F2).** jsx와 hook에 남은 판단은 테스트할 수 없다.
- **E9. 템플릿이 만든 앱 서버 코드는 고치지 않는다.** 확장이 쓰지 않는 템플릿 코드에 우리 코드를 섞지 않는다.

## 2. 값과 설정

- **E3. 닫힌 값 목록은 상수 객체 한곳에 두고 JSDoc union으로 타입을 단다(V3).** JSDoc 타입 표기는 도구가 읽는 주석이라 K4에 든다. 빠뜨린 값은 목록 전체를 도는 테스트로 잡는다.
- **E4. 빌드 때 치환되는 환경 값은 한곳에서 읽는다(V1, S8).** 값이 없으면 기능을 끈다. 환경별 분기는 번들에서 빠지도록 치환 값과 직접 비교하는 식으로 쓴다.
- **E5. 운영자 설정(확장 toml의 settings)은 코드의 키와 짝이 맞는지 테스트로 묶는다(T7).** 번역 파일은 언어끼리 키와 자리표시자가 같은지 테스트로 묶는다.
- **E6. 문구는 번역 파일이 기본이고 운영자 설정이 덮어쓴다(F1).** 어느 언어에서 운영자 설정을 쓰는지 한 함수에서 정한다.

## 3. 편집기

- **E7. 편집기(운영자 미리보기)에서는 서버를 부르지 않고, 운영자가 고른 상태만 그린다.** 편집기인지 판단하는 함수는 하나만 둔다(S6).

## 4. 테스트

- **E8. 테스트는 `node:test`로 utils와 services를 대상으로 쓴다(T3, F5).** 네트워크 호출과 `shopify` 전역만 가짜로 바꾼다.

## 5. 직접 쓰지 않는 것 (S9)

| 직접 쓰지 않는 것 | 대신 쓸 것 | 규칙 |
|---|---|---|
| jsx와 components 안의 `useEffect` | `hooks/`의 이름 붙은 hook. `useEffect`는 `hooks/` 안에서만 쓴다 | S9 |
| `services/` 밖의 `fetch` | `services/`의 클라이언트 | F3, F4 |
| `config/` 밖의 `process.env` | `config/`에서 읽어 내놓은 값 | E4 |
| `setTimeout`, `setInterval` | 제한 시간은 `services/`의 클라이언트 한곳, 폴링과 대기 표시는 `hooks/`의 이름 붙은 hook | S10 |

## 프로젝트가 정하는 것

- 환경별 서버 주소와 허용 호스트 목록을 두는 자리
- 배포 도구(Shopify CLI) 실행과 실제 환경 파일 읽기를 기본 테스트 실행에 넣을지(T5)
- 로그 문구의 언어
