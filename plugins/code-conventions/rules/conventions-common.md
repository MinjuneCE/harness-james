# 코드 컨벤션: 공통 규칙

제품 코드를 새로 쓰거나 고칠 때 따르는 규칙이다. 근거와 전체 내용은 `{{CONVENTIONS_DIR}}/common.md`에 있다. 번호는 그 문서의 번호다.

- 적용 대상은 제품 코드다. 개인 도구 코드(에이전트 하네스, 스킬, 훅, `.claude/`·`.research/`·`.loop/` 아래의 스크립트)는 대상이 아니다.
- 컨벤션은 앞으로 하는 개발의 기준이다. 이미 있는 코드와 커밋은 그대로 두고, 규칙에 맞추려고 따로 정리하지 않는다. 기존 코드에 이 규칙과 다른 모습이 있어도 베끼지 않는다.
- 프로젝트 문서가 예외나 프로젝트 선택을 적어 두었으면 그 문서를 따른다.

## 구조와 경계

- S1. 의존은 입출력·프레임워크 → 유스케이스 → 판단 코드 한 방향으로만 간다. 격리할 모듈은 폴더로 나눈다.
- S2. 업무 판단은 프레임워크와 화면 없이 돌 수 있는 코드 한곳(도메인 클래스, 순수 함수)에 둔다.
- S3. 인터페이스, 주입 인자 같은 갈아 끼우는 자리는 쓰는 곳이 둘 이상이거나 진짜 경계(외부 API, DB, 시계)일 때만 만든다.
- S4. 경계의 이름은 공급자 이름이 아니라 업무 말로 짓는다.
- S5. 외부 응답, 상태 문자열, 오류 코드, 예외는 경계에서 우리가 정한 모양의 값으로 바꿔 넘긴다.
- S6. 같은 일을 하는 방법은 하나만 둔다. 새 방식으로 옮기면 같은 변경에서 옛 방식을 지운다.
- S7. 상태는 한곳(타입의 메서드, 순수 함수 하나)에서 정하고, 다른 코드는 읽기만 한다.
- S8. 모르는 값, 빠진 설정, 실패한 외부 조회는 안전한 쪽(숨김, 호출 안 함)으로 떨어진다. 일부만 받은 값으로 판단하지 않는다.
- S9. 오용하기 쉬운 기능은 감싼 한곳에서만 쓴다. 무엇이 해당하는지는 스택 규칙의 "직접 쓰지 않는 것"에 있다.
- S10. 다른 코드가 준비되기를 기다리려고 타이머나 sleep을 쓰지 않는다. 테스트도 같다. 제한 시간, 정책이 정한 간격, 입력 묶기는 이름 붙은 한곳에서만 쓴다.
- S11. 다른 시스템이 최종 판정하는 규칙을 복제할 때는 원본보다 넓게 허용하지 않는다. 넓지 않음을 테스트로 고정하고 원본이 무엇인지 테스트 이름에 밝힌다.

## 값

- V1. 운영·정책 값(시간, 간격, 횟수, 목록)은 코드 리터럴로 두지 않고 설정으로 받는다. 없으면 안 되는 값은 시작할 때 검증한다.
- V2. 기본값은 한 곳에만 둔다. 시크릿은 환경 변수로만 받고 코드와 저장소에 넣지 않는다.
- V3. 업무 상태와 사유 코드는 닫힌 값 목록 한곳에 둔다. 흩어진 문자열로 두지 않고 설정으로 빼지도 않는다.
- V4. 외부 시스템의 문자열은 경계 코드 안에만 둔다.
- V5. DB 값, 응답 값, 저장소 키, 이벤트 이름처럼 바깥에 남는 문자열은 한곳에 고정한다. 관측용 라벨은 그 값을 쓰는 계층에 둔다.
- V6. 정책은 상태와 업무 사실로 분기한다. 단계 이름, 경로, 파일 이름 같은 코드 위치로 가르지 않는다.

## 테스트

- T1. 구현은 실패하는 테스트부터 쓴다. 기능과 버그 수정 모두 그렇다.
- T2. 커밋은 테스트 커밋, 구현 커밋 순서로 남긴다. 브랜치의 마지막 커밋은 테스트가 통과하는 상태여야 한다.
- T3. 테스트는 동작(보낸 요청, 저장된 상태, 응답, 오류 종류, 외부와의 순서, 사용자에게 보이는 문구)을 단언한다. 내부 호출 여부와 로그 문구는 단언하지 않는다.
- T4. 경계 자리에는 가짜(메모리용 구현, 주입한 함수)를 먼저 쓴다. 목은 외부 경계에만 쓴다.
- T5. 기본 테스트 실행은 실제 외부 시스템을 부르지 않는다.
- T6. 테스트 이름은 영어로 행위를 서술한다. 설명은 단언 메시지에 쓴다. 이미 있는 다른 언어의 이름은 그대로 둔다.
- T7. 코드가 읽는 선언 파일(설정 스키마, 번역 파일, 매니페스트)과 코드의 짝을 테스트로 묶는다.

## 주석

- K1. 주석은 쓰지 않는다. 테스트 안도 같다.
- K2. 이유는 다른 자리에 적는다. 외부 때문에 이상해 보이는 코드의 이유는 그 동작을 고정하는 테스트의 이름과 단언 메시지에, 계약은 계약 테스트에, 링크와 배경은 커밋 메시지에 적는다.
- K3. 이상해 보이는 코드를 남겨야 하면 그 동작을 고정하는 테스트를 둔다.
- K4. 예외는 도구가 읽는 주석뿐이다. 타입 표기(JSDoc 타입), lint 지시문과 그 이유, 라이선스 머리말이다.
- 팀이 열 수 없는 번호(작업 공간의 설계 문서 번호)는 코드와 테스트 이름에 쓰지 않는다.

## 커밋

- C1. 커밋 하나에는 목적 하나만 담고, diff는 가장 작게 만든다.
- C3. 옮기기와 옛것 지우기는 한 변경에서 한다.

## 외부 호출과 보안

- X1. 모든 외부 호출에 제한 시간을 둔다. 시간 초과는 다른 실패와 나눠 다룬다.
- X2. 개인정보와 비밀값은 로그, 예외 메시지, 브라우저 저장소, 분석 이벤트에 그대로 남기지 않는다.
- X3. 바깥에서 온 값을 다른 언어의 코드(HTML, 스크립트, SQL, 셸 명령)에 넣을 때는 그 언어용 인코딩을 거친다.
