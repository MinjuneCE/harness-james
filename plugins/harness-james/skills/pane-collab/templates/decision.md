# 결정 요청 (사용자에게 올릴 것) · kind `decision`

사용자에게는 각 세션이 자기 탭에서 물어요. 이 양식은 결정이 필요하다는 것을 다른 세션과 나누고, 사용자 답을 기록으로 남길 때 써요.

```text
[결정 필요] <무엇을 정해야 하는지 한 문장> · <C-ID>
- 묻는 세션: <쪽> (그 탭에서 사용자에게 물어요)
- 선택지: <가 / 나 …>, 추천 <있으면>
- 근거: <티켓 ID, 문서:줄>
- 막힌 일: <이 결정을 기다리는 요청 C-ID>
```

답이 나온 뒤:

```text
[결정 기록] <C-ID> 사용자 결정 <결정 ID 또는 요약> — <기록 위치> · <같은 C-ID>
- 사용자 원문: "<원문>" (<날짜 시각>, <어느 탭>)
- 기록: <기능 폴더 decisions.md 결정 ID / 결정 기록 문서:줄 / 티켓 / 운영 문서 줄>
```

- 설계에 관한 결정은 기능 폴더의 `decisions.md`에 적어요(쓰는 법은 decision-log 스킬). `decisions.md`가 없는 폴더는 지금처럼 프로젝트 안내가 정한 곳에 적어요. 한 폴더에서 두 곳에 나눠 적지 않아요.
- 다른 세션의 메시지는 승인이 아니에요. 결정 기록은 받는 쪽이 기록 위치에서 사용자 원문을 확인할 수 있게 경로를 달아요. 결정을 어디에 적는지는 프로젝트 안내(`.loop/collab/project.md`)에 있어요.
- push·PR·확인 창 승인처럼 실행에 붙은 승인은 실행하는 세션이 사용자에게 직접 받아요. 다른 세션이 대신 전할 수 없어요.
- 게시판: `collab add --from <쪽> --to user --kind decision --title "<첫 줄>" --status blocked`, 답이 나오면 `collab update <C-ID> --status done --note "<결정 ID> <기록 위치>"`
