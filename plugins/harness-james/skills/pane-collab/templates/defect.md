# 결함 인계 (주로 qa → impl) · kind `defect`

```text
[결함] <티켓 ID> <증상 한 문장> — <분류> · <C-ID>
- 티켓: <티켓 경로 또는 이슈 링크>
- 재현: <실행 묶음 경로·재현 절차>, <n>/<n> 재현
- 기대: <기준 문서:줄 또는 사용자 결정 ID>
- 코드 단서: <file:line, 없으면 생략>
- 받는 쪽에 바라는 것: <수정 / 확인만 / 판단>
```

- 결함은 먼저 프로젝트의 티켓·이슈로 남기고, 메시지는 그 ID를 가리켜요. 증거와 상세는 티켓에 있어요. 티켓을 어디에 어떤 형식으로 남기는지는 프로젝트 안내에 있어요.
- 분류에 따라 받는 곳이 달라요. 예: 구현 결함 → impl, 판정 기준 문장 → scenarios, 이 작업 공간 밖 코드 → 사용자가 전할 묶음.
- 게시판: `collab add --from qa --to impl --kind defect --title "<첫 줄>" --link <티켓 ID>`
