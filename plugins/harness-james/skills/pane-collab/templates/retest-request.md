- 시험 대상: <worktree>@<HEAD> (기준 <브랜치>)
- 바뀐 커밋: <해시 제목> …
- 해시가 바뀐 것: <옛 → 새, 코드 같음 여부. 없으면 생략>
- 다시 띄울 것: <서버 재시작(env 추가, 캐시) / 미리보기 재시작 / 새 DB 마이그레이션 / 없음>
- env·스키마·설정 키: <그대로 / 바뀐 것>
- 외부 호출 순서·횟수 변화: <예: 실패한 요청은 재시도마다 호출이 1회씩 늘어요 / 없음>

- 데이터 전제: <예: 실패 상태의 레코드는 다시 요청해도 그대로라 새 데이터가 필요해요 / 없음>
- 다시 돌릴 것과 기대: <시험·요청서 → 기대 한 줄씩, 길면 파일 경로>
- 바꾸지 않은 것: <알려진 차이와 근거 사용자 결정 ID. 결함으로 다시 올리지 않게>

- 해당 없는 칸은 지워요. 상세는 `.research/out/impl-for-qa.md`처럼 `<보내는 역할>-for-<받는 역할>.md`에 두고 경로만 실어요.
- 게시판: 원래 요청은 `collab update <원래 C-ID> --status doing --note "재시험 대기 <HEAD>"`로 두고, 이 요청을 새 항목으로 남겨요. 재시험이 PASS면 impl이 원래 요청을 `done`으로 바꿔요.
