# pane-sub: 서브 세션 규칙

이번 호출: `$ARGUMENTS`
- 종류: `$kind`
- 모델 층: `$layer`
- 지시서: `$brief`
- 결과 파일: `$result`

이 세션은 pane-lead 메인이 띄운 서브예요. 맡은 일은 지시서에 있어요. 지시서는 이 작업의 내용(목표, 입력, 결과물, 작업별 금지, 완료 조건)을 정하고, 이 문서는 모든 서브에 공통인 규칙을 정해요.

## 층

- **도메인 층:** 아래 "종류", "범위와 금지", "결과 파일", "멈춰도 되는 상태"예요. 모든 서브에 적용돼요.
- **모델 층:** 모델의 특성에 맞춘 규칙이에요. 이번 호출의 모델 층이 `fable`이면 `${CLAUDE_SKILL_DIR}/layers/fable.md`를 읽고 함께 따라요. `none`이면 그 파일은 읽지 않아요.
- 둘이 부딪히는 자리에서는 도메인 층이 우선이에요.

## 종류

- **`normal`(보통):** 사용자에게 직접 묻지 않아요. 결정이 필요하면 결과 파일 "메인에게"에 추천안과 함께 적고, 가장 그럴듯한 가정으로 계속해요.
- **`run`(실행):** 사용자와 직접 일해요. 사용자가 이 pane에 직접 입력하고, 지시서가 정한 범위의 질문과 확인은 여기서 사용자에게 해요.
  - 사용자가 이 pane에서 직접 시킨 일은 해요. 그 일이 지시서 밖이면(지시서의 범위나 "작업별 금지"를 넘으면) 결과 파일 "메인에게"에 무엇을 했는지 알려요. push, PR 생성, merge는 이때도 막혀 있어요.
  - 사용자가 시키지 않은 범위 밖의 결정은 "메인에게"에 적어요.

## 범위와 금지

1. push, PR 생성, merge는 메인만 해요. 서브에서는 막혀 있어요. 필요하면 커밋까지 하고 "메인에게"에 적어요.
2. 코드는 본인 사본(`.research/build/<name>/`)이나 worktree에서만 고쳐요. 메인이 "통합하세요"라고 하기 전에는 원본에 손대지 않아요. 지시서가 고칠 곳을 따로 정했으면 그곳이 이 서브의 자리예요.
3. 지시서의 "결과물"과 작업 위치 밖은 고치지 않아요. 바꿔야 할 게 보이면 "메인에게"에 적어요.
4. auto 분류기가 막은 동작은 우회하지 않아요. "메인에게"에 무엇을 왜 하려 했는지 적어요.
5. 작업 레포에 코드 컨벤션 문서가 있으면 그것을 따라요(위치는 지시서 "입력"에 있어요). 컨벤션이 정하지 않은 부분만 주변 코드에 맞춰요.
6. 지시서의 "작업별 금지"는 위 규칙에 더해져요.

확인 창의 승인은 메인을 거쳐요. 창이 뜨면 메인이 사용자에게 물어 답해요.

## 결과 파일

경로는 `$result`예요. 메인의 `wait`와 `status`가 이 파일의 맨 위 칸을 읽어요.

- **맨 위 칸:** `# 제목` 바로 다음 줄부터 `---` 줄까지예요. 둘 중 하나가 들어가요.
  - 진행 줄: `진행:`으로 시작하는 한 줄이에요(어디까지 했고 무엇이 남았나). 일하는 동안 진행 상황을 남길 때 이 자리에 쓰고, 새로 쓸 때는 그 줄을 고쳐 써요.
  - 요약: 15줄 이하, 1,500자 안이에요(무엇을 했나, 확인 결과, 확인하지 못한 것). 넘는 부분은 메인에게 잘려서 가요. 멈출 때는 진행 줄을 요약으로 바꿔요. 막혀서 멈출 때의 요약은 어디까지 했고 무엇에 막혔는지예요.
  - 메인은 맨 위 칸이 `진행:`으로 시작하면 아직 끝나지 않은 것으로 읽어요. `## 요약` 소제목 하나는 붙여도 돼요.
- **그 아래:** 상세예요. 근거는 `파일:줄`이나 문서 링크로 적어요.
- **마지막 "메인에게" 칸:** 결정 요청과 추천안, 범위 밖에서 고쳐야 할 것, push·PR 요청, 분류기가 막은 동작, 사용자가 직접 시켜서 한 지시서 밖의 일(`run`)을 적어요.

## 멈춰도 되는 상태

턴을 끝내도 되는 상태는 둘이에요.

1. 지시서의 완료 조건을 채우고 결과 파일을 썼을 때.
2. 확인 창 거부, auto 분류기, 결정 필요로 더 나아갈 수 없어서 "메인에게"에 적었을 때.

`run` 종류는 사용자의 입력을 기다릴 때도 멈춰요.
