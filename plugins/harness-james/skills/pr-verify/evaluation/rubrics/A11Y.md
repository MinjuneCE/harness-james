  - 카트·모달 같은 인터랙션의 **동작** 오류(담기 실패, 수량 경합) → REL. 키보드·보조기술로 **조작할 수 없는** 경우는 여기(A11Y-04)다.

## A11Y-01 이미지 대체 텍스트·텍스트 이미지

- **적용**: 클라이언트
- **왜 중요한가**: 상품·프로모션 이미지는 상품명, 할인율, 증정 조건을 담는다. 대체 텍스트가 없으면 스크린리더 사용자는 그 정보를 모른다. 텍스트를 이미지로 만든 배너는 할인 조건 자체가 사라진다.
- **판정 질문**:
  - 이 PR이 추가·변경한 이미지(`<img>`, 템플릿 헬퍼가 만드는 이미지, `<svg>`, CSS 배경 이미지)가 정보성이면 의미 있는 대체 텍스트를, 장식이면 빈 `alt=""`(또는 `aria-hidden="true"`)를 갖는가?
  - 할인율·금액·조건을 **이미지 안의 텍스트로만** 전달하는가?

**체크포인트**
- 이미지 헬퍼가 alt를 생략하면 미디어 alt나 리소스 제목으로 채우는 경우가 있다. 상품 이미지라면 통과다. 다만 상품 제목과 다른 정보를 담은 이미지(라이프스타일, 성분 인포그래픽)는 alt를 명시하는 것을 권장한다(low).
- 직접 쓴 `<img>`에는 `alt` 속성이 반드시 있어야 한다. CMS·설정으로 들어오는 이미지는 저장된 alt를 escape해 쓰고, 비면 섹션 제목·상품명 같은 맥락 값으로 대체한다.
- 장식 이미지(구분선, 배경 텍스처)는 `alt=""`로 둔다. `alt="image"`, `alt="banner"`, 파일명 alt는 정보 없음으로 본다.
- 인라인 아이콘 `<svg>`: 옆에 텍스트가 있으면 `aria-hidden="true" focusable="false"`, 아이콘만 있으면 부모 버튼·링크에 이름이 필요하다(A11Y-02).
- 프로모션 배너의 할인·조건 텍스트가 이미지에만 있으면 1.4.5 위반이다. 같은 정보를 HTML 텍스트나 alt로 전부 제공해야 한다.
- `<video>`의 포스터·fallback 이미지도 alt를 갖는다.

**심각도 앵커**
- critical: 사용하지 않음.
- high: 핵심 흐름(상품 화면, 카트)의 상품 이미지·버튼 이미지에 alt가 없어 **어떤 상품인지 알 수 없음**(카드 그리드 전체, 카트 라인 아이템). 피크 프로모션의 할인·증정 조건을 텍스트 이미지로만 전달.
- medium: 정보성 이미지(성분·사용법·프로모션 일부)의 alt 누락, 무의미한 alt(파일명·"image").
- low: 장식 이미지에 alt 텍스트가 있음(중복 낭독), 헬퍼 기본 alt가 맥락상 부족.

**피크 트래픽 관점**: 대형 할인 시즌 랜딩·배너는 짧은 기간 트래픽이 몰리고 텍스트 이미지 비중이 높다. 접근성 감사 스캔이 노리는 페이지이기도 하다. 시즌 모드에서는 프로모션 화면의 텍스트 이미지 전용 할인 조건을 high로 본다.

**근거**: WCAG 2.2 SC 1.1.1 Non-text Content(A), 1.4.5 Images of Text(AA) — https://www.w3.org/TR/WCAG22/ . WAI Images Tutorial(정보성·장식 이미지 구분) — https://www.w3.org/WAI/tutorials/images/ .

## A11Y-02 접근 가능한 이름·역할·상태

- **적용**: 클라이언트
- **왜 중요한가**: 아이콘 버튼(닫기, 수량 +/-, 위시리스트, 캐러셀 화살표)과 "Shop now"가 반복되는 카드 링크는 이름이 없거나 같으면 스크린리더 사용자가 구분할 수 없다. 외부 접근성 감사에서 가장 자주 지적되는 항목이다.
- **판정 질문**:
  - 새·변경 `<button>`·`<a>`·폼 컨트롤·커스텀 위젯이 **보이는 텍스트 또는 `aria-label`/`aria-labelledby`로 고유하고 의미 있는 이름**을 갖는가?
  - 커스텀 위젯(클릭 가능한 `div`·`span`, 아코디언, 탭, 토글)에 올바른 역할(`button`, `tab`, `dialog`)과 상태(`aria-expanded`, `aria-selected`, `aria-pressed`, `aria-current`)가 있고, 상태가 바뀔 때 갱신되는가?
  - 폼 입력(뉴스레터, 수량, 검색, 메모)에 연결된 `<label>`이나 `aria-label`이 있는가?

**체크포인트**
- 반복 CTA는 "버튼 문구 — 섹션/상품 맥락"으로 이름을 만든다. 레포에 이미 이런 맥락 이름 패턴이 있으면 새 카드·업셀·추천 컴포넌트도 같은 방식을 따른다.
- 아이콘 전용 버튼에는 번역을 거친 `aria-label`이 필요하다. 수량 증감, 삭제, 캐러셀 이전/다음, 영상 재생/정지, 모달 닫기를 확인한다.
- 클릭 가능한 `div`/`span`(인라인 클릭 핸들러, 프레임워크 이벤트 바인딩, 클릭 리스너)은 `<button>`으로 바꾸거나 `role="button" tabindex="0"`과 Enter/Space 처리를 둔다(키보드 처리는 A11Y-04).
- 링크를 버튼으로 쓰지 않는다(`href="#"`, `href="#!"` + 스크립트). 링크 URL 기본값을 `#`류로 두는 것도 같다.
- 아코디언·탭은 `aria-expanded`/`aria-controls`나 `<details>/<summary>`를 쓴다.
- `aria-label`이 보이는 텍스트와 다르면 보이는 텍스트를 포함해야 한다(음성 입력 사용자). 예: 보이는 "Shop" ↔ `aria-label="Shop <상품명>"`은 통과, `aria-label="View details"`는 위반.
- `aria-label` 문자열은 번역을 거쳐야 한다. 하드코딩 aria-label 자체는 A11Y-08로, 이름이 없는 것은 여기로 보낸다.
- `aria-hidden="true"`를 포커스 가능한 요소나 그 조상에 두면 안 된다.

**심각도 앵커**
- critical: 핵심 흐름의 담기·결제·수량 컨트롤이 **모든 상품 화면 또는 카트에서** 이름·역할이 없어 스크린리더로 구매할 수 없음.
- high: 담기·빠른 담기·카트 수량·카트 닫기·국가/언어 선택기 같은 핵심 흐름 컨트롤 하나의 이름 누락. 레포의 맥락 이름 패턴 없이 새 카드·CTA 컴포넌트를 추가해 같은 이름의 링크가 반복됨.
- medium: 그 밖의 아이콘 버튼·링크 이름 누락, 커스텀 위젯의 역할·상태 누락, 라벨 없는 폼 입력.
- low: 이름은 있으나 맥락이 부족(같은 이름 2~3개), 보이는 텍스트와 이름 불일치.

**피크 트래픽 관점**: 피크 랜딩은 카드 그리드·CTA를 대량으로 복제한다. 이름 패턴 없이 복제하면 결함이 페이지 수만큼 늘어난다. 시즌 모드에서는 시즌용 카드 컴포넌트의 이름 누락을 high로 본다.

**근거**: WCAG 2.2 SC 4.1.2 Name, Role, Value(A), 2.4.4 Link Purpose (In Context)(A), 2.4.6 Headings and Labels(AA), 3.3.2 Labels or Instructions(A), 2.5.3 Label in Name(A). WAI-ARIA Authoring Practices Guide — https://www.w3.org/WAI/ARIA/apg/ .

## A11Y-03 문서 구조 (h1·헤딩 순서·`lang`)

- **적용**: 클라이언트
- **왜 중요한가**: 스크린리더 사용자는 헤딩으로 페이지를 훑는다. h1이 없거나 여러 개면 페이지 주제를 놓친다. `lang`이 틀리면 독일어 페이지를 영어 발음으로 읽는다.
- **판정 질문**:
  - 이 PR이 바꾼 템플릿·컴포넌트 조합에서 페이지당 h1이 정확히 하나인가?
  - 헤딩을 시각 크기 때문에 고르지 않았는가? 레벨을 건너뛰거나(h2 → h4) 헤딩이 아닌 텍스트에 헤딩 태그를 쓰면 안 된다.
  - `<html lang>`이 요청 locale을 반영하는가? 다른 언어 구간(외국어 상품명 등)에 `lang`이 있는가?

**체크포인트**
- `<html lang>`은 요청 locale → 상점·앱 기본 locale → 고정 기본값 순의 fallback으로 항상 값을 갖는다. 모든 레이아웃(본 레이아웃, 대체 레이아웃, 비밀번호·오류 페이지)이 같은 규칙을 따라야 한다. 이 경로를 바꾸는 변경은 A11Y-07에서도 본다.
- 컴포넌트 제목 레벨을 설정으로 고르게 하는 패턴(h1/h2/h3 선택, 기본 h2)이 있으면 새 컴포넌트도 따른다. 설정으로 h1을 지정하면 같은 페이지의 다른 h1(상품명, 컬렉션명, 페이지 제목)과 겹치지 않는지 확인한다.
- 페이지 유형마다 h1의 출처가 하나로 정해져 있어야 한다(상품 화면은 상품명, 목록은 목록 제목, 일반 페이지는 컴포넌트 h1 또는 visually-hidden h1). h1이 없는 새 페이지 템플릿을 만들면 h1 출처를 둔다.
- 차단·오류 안내 같은 대체 화면도 h1을 갖는다.
- 설정 값을 헤딩에 넣을 때 빈 값이면 빈 헤딩 태그가 남지 않게 가드를 둔다.

**심각도 앵커**
- critical: 사용하지 않음.
- high: `<html lang>`이 빠지거나 고정값(`lang="en"`)으로 바뀌어 비영어 locale 전체가 잘못 낭독됨. 모든 상품 화면 또는 모든 목록 화면에서 h1이 사라짐.
- medium: 특정 템플릿에서 h1 0개 또는 2개 이상, 헤딩 레벨 건너뜀, 시각용 헤딩 남용, 빈 헤딩.
- low: 부분 언어 표시(`lang` on 구간) 누락, 헤딩 텍스트가 모호함.

**피크 트래픽 관점**: 시즌 랜딩은 페이지 빌더나 새 컴포넌트 조합으로 급히 만들어져 h1이 0개이거나 배너마다 h1인 경우가 흔하다. 시즌 모드에서는 프로모션 화면의 h1 결함을 medium 이상으로 본다.

**근거**: WCAG 2.2 SC 1.3.1 Info and Relationships(A), 2.4.2 Page Titled(A), 2.4.6 Headings and Labels(AA), 3.1.1 Language of Page(A), 3.1.2 Language of Parts(AA). WAI Page Structure Tutorial — https://www.w3.org/WAI/tutorials/page-structure/headings/ .

## A11Y-04 키보드 조작·포커스 관리

- **적용**: 클라이언트
- **왜 중요한가**: 카트 드로어, 빠른 담기 모달, 메가메뉴, 국가 선택기는 핵심 흐름의 관문이다. 키보드로 열 수 없거나, 열린 뒤 포커스가 뒤 페이지로 새거나, Esc로 닫히지 않거나, 닫힌 뒤 포커스가 사라지면 키보드·스크린리더 사용자는 구매를 끝낼 수 없다.
- **판정 질문**:
  - 새·변경 인터랙션이 키보드만으로 조작되는가? Tab으로 도달, Enter/Space로 실행, 방향키(해당 시)로 이동해야 한다.
  - 드로어·모달·팝업이 열릴 때 포커스를 안으로 옮기고, 열린 동안 가두고(trap), Esc로 닫히며, 닫히면 연 요소로 포커스를 되돌리는가?
  - 포커스 순서가 DOM 순서와 맞고, 숨겨진 요소(닫힌 드로어, 화면 밖 슬라이드)에 포커스가 가지 않는가? 양수 `tabindex`가 없어야 한다.

**체크포인트**
- 레포나 기반 프레임워크에 공통 포커스 가두기·Esc·포커스 복귀 유틸이 있으면 새 드로어·모달은 그것을 재사용한다. **커스텀 코드가 이 흐름을 우회하거나 덮어쓰면 위반이다.** 우회의 예: 상태 클래스만 붙여 직접 열기, 이벤트 전파 차단으로 Esc 무력화, 열 때 포커스 이동 없음.
- 새 모달·팝업·드로어(오버레이, 쿠키 배너, 뉴스레터·프로모션 팝업, 서드파티 위젯 래퍼)는 네이티브 `<dialog>` 또는 `role="dialog" aria-modal="true" aria-labelledby`를 쓴다.
- 메가메뉴·모바일 메뉴: 하위 메뉴가 hover로만 열리면 위반이다. 버튼 + `aria-expanded`로 키보드 열기를 제공한다.
- 캐러셀·슬라이드쇼: 화면 밖 슬라이드의 링크·버튼은 `inert`나 `tabindex="-1"`로 탭 순서에서 빠져야 한다. 이전/다음 컨트롤은 `<button>`이어야 한다.
- 영상: 네이티브 controls가 없으면 키보드로 쓸 수 있는 재생/정지 버튼을 제공한다.
- 양수 `tabindex`(`tabindex="1"` 등)는 금지한다.
- 포커스가 sticky 헤더·쿠키 배너·알림에 가려지지 않아야 한다(2.4.11). `scroll-padding-top`이나 `scroll-margin`으로 확보한다.

**심각도 앵커**
- critical: 모든 상품 화면 또는 카트에서 키보드로 담기·결제 진입이 불가능. 예: 드로어가 열리면 포커스가 배경에 남고 드로어 버튼에 도달할 수 없음, 키보드 트랩으로 빠져나갈 수 없음.
- high: 카트 드로어·빠른 담기·국가/언어 선택기·메가메뉴 중 하나에서 포커스 이동·가두기·Esc·복귀 중 하나가 깨짐. 새 모달이 공통 포커스 관리 유틸을 쓰지 않음. 마우스 hover로만 열리는 내비게이션.
- medium: 그 밖의 위젯(아코디언, 탭, 캐러셀)의 키보드 조작 불가. 화면 밖 슬라이드에 포커스 진입. 양수 `tabindex`. sticky 요소에 포커스가 가려짐.
- low: 포커스 순서가 시각 순서와 약간 다름, 불필요한 탭 정지.

**피크 트래픽 관점**: 피크에는 프로모션 팝업·증정품 알림·카운트다운 배너·쿠키 배너가 동시에 뜬다. 겹친 오버레이의 포커스 충돌이 평시보다 잘 생긴다. 시즌 모드에서는 오버레이·증정 알림 변경의 포커스 결함을 high로 본다.

**근거**: WCAG 2.2 SC 2.1.1 Keyboard(A), 2.1.2 No Keyboard Trap(A), 2.4.3 Focus Order(A), 2.4.11 Focus Not Obscured (Minimum)(AA). WAI-ARIA APG Dialog (Modal) Pattern(열면 포커스 이동, 안에 가둠, Esc로 닫고 연 요소로 복귀) — https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/ . APG Disclosure Pattern(hover 없이 여는 메뉴) — https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/ .

## A11Y-05 상태 알림·자동 움직임·시간 제한

- **적용**: 클라이언트
- **왜 중요한가**: 카트에 담기, 수량 변경, 가격·재고 변경, 무료배송 진행이 시각적으로만 바뀌면 스크린리더 사용자는 성공 여부를 모른다. 반대로 카운트다운이 매초 낭독되면 페이지를 쓸 수 없다. 자동 재생 영상·슬라이드는 정지 수단이 필요하다.
- **판정 질문**:
  - 동적 갱신(카트 개수·합계, 담기 결과, 오류, 옵션 선택 시 가격·재고, 검색 결과 수)이 `aria-live`·`role="status"`·`role="alert"`로 알려지는가?
  - `aria-live` 영역이 너무 자주 바뀌지 않는가? 매초 갱신하는 카운트다운, 연속 애니메이션이 대상이다.
  - 5초 넘게 자동으로 움직이는 콘텐츠(캐러셀, 배경 영상, 마키, 애니메이션)에 일시정지·정지·숨김 수단이 있는가? 시간 제한(세션 만료, 카운트다운 기반 예약)에 조정 수단이 있는가?

**체크포인트**
- 카트·검색 결과처럼 서버가 부분 HTML을 다시 렌더하거나 클라이언트가 DOM을 교체하는 경로는, 기존 live region을 교체 대상 밖에 두거나 교체 후에도 유지해야 한다. live region이 응답과 함께 통째로 바뀌면 알림이 사라진다.
- 옵션 선택 시 가격·재고 변경은 live region이나 버튼 텍스트 변경(예: Sold out)으로 전달한다.
- 무료배송 진행 메시지는 카트 갱신과 함께 바뀐다. 메시지가 live region 밖이면 low다.
- 카운트다운: 숫자 셀 전체에 `aria-live`를 두면 매초 낭독된다. live region은 "종료됨" 같은 상태 전환에만 두고, 숫자는 `aria-hidden`과 정적 텍스트 대체(예: "Ends Dec 1, 11:59 PM PST")를 쓴다.
- 자동 재생 배경 영상·자동 넘김 슬라이드에는 키보드로 쓸 수 있는 일시정지 버튼이 있어야 한다(2.2.2, A 필수). `prefers-reduced-motion: reduce`일 때 자동 재생·전환 애니메이션을 멈추는 것을 권장한다(2.3.3은 AAA라 권장).
- 미디어는 기본적으로 자동 재생하지 않는다. 필요하면 음소거로 시작한다. 소리가 나는 자동 재생은 high다.
- 빈 자막 트랙(`src=""`)은 자막 제공이 아니다(1.2.2).

**심각도 앵커**
- critical: 사용하지 않음.
- high: 카트 담기·수량 변경 결과 알림 제거(기존 live region 삭제 포함). 소리 나는 자동 재생. 전 페이지 레이아웃·홈 히어로의 정지 수단 없는 자동 캐러셀·영상.
- medium: 옵션 가격·재고 변경 미알림, 오류 메시지 미알림. 매초 낭독되는 live region. 그 밖의 정지 수단 없는 자동 움직임.
- low: 무료배송 진행 메시지 미알림, `prefers-reduced-motion` 미대응.

**피크 트래픽 관점**: 시즌에는 카운트다운·자동 캐러셀·배경 영상이 가장 많다. 시즌 모드에서는 새 카운트다운의 숫자 live region, 정지 수단 없는 자동 배너를 한 단계 올린다.

**근거**: WCAG 2.2 SC 4.1.3 Status Messages(AA), 2.2.1 Timing Adjustable(A), 2.2.2 Pause, Stop, Hide(A), 1.2.2 Captions (Prerecorded)(A), 1.4.2 Audio Control(A), 2.3.3 Animation from Interactions(AAA, 권장 근거로만). WAI-ARIA 1.2 live region 속성 — https://www.w3.org/TR/wai-aria-1.2/ .

## A11Y-06 시각 표현 (대비·포커스 표시·확대·타깃 크기)

- **적용**: 클라이언트
- **왜 중요한가**: 프로모션 배너는 브랜드 색 위 흰 글씨, 그라데이션 위 작은 가격 문구를 많이 쓴다. 저시력 사용자는 할인 조건을 읽지 못한다. 포커스 테두리를 지우면 키보드 사용자가 위치를 잃는다.
- **판정 질문**:
  - 새·변경 CSS·인라인 스타일·색 설정 기본값의 텍스트 대비가 4.5:1(큰 텍스트 3:1) 이상인가? 아이콘·입력 테두리·포커스 표시는 3:1 이상인가?
  - `outline: none`/`0`으로 포커스 표시를 지우면서 `:focus-visible` 대체 스타일을 주지 않는가?
  - 확대(200%)·좁은 화면(320 CSS px)에서 내용이 잘리지 않는가? 고정 높이 + `overflow: hidden`, `user-scalable=no`가 없어야 한다.
  - 색만으로 정보를 전달하지 않는가? 예: 품절을 회색으로만 표시, 색상 스와치에 이름이 없음.

**체크포인트**
- 대비 판정은 diff에 **색 값이 명시된 경우**에만 계산한다. 텍스트 색·배경 색이 둘 다 코드·설정 기본값에 있어야 한다. 운영자가 편집기에서 정하는 색은 기본값만 본다. 계산이 불가능하면 `confidence: possible`.
- 진행바·배지·그라데이션 위 텍스트의 대비를 본다.
- 색상 스와치: 색 칩에 이름(`aria-label` 또는 보이는 텍스트)이 함께 있어야 한다(1.4.1).
- 뷰포트 메타에 `user-scalable=no`·`maximum-scale=1`이 생기면 위반이다.
- 타깃 크기: 새 아이콘 버튼·스와치·캐러셀 점은 24×24 CSS px 이상이거나 간격으로 보완한다(2.5.8).
- hover·focus로 뜨는 툴팁·미니카트는 닫을 수 있고, 마우스를 올려도 사라지지 않아야 한다(1.4.13).
- 벤더 기본 스타일시트의 `outline: none`은 `pre-existing`이다. 커스텀 스타일에서 새로 지우는 것만 감점한다.

**심각도 앵커**
- critical: 사용하지 않음.
- high: 전역 스타일에서 포커스 표시 제거(`*:focus { outline: none }` 류). 담기·결제 버튼 텍스트 대비 3:1 미만. 확대 차단 뷰포트.
- medium: 특정 컴포넌트의 대비 미달(가격·할인 조건 텍스트), 포커스 표시 제거, 색만으로 상태 전달, 320px 리플로 깨짐.
- low: 장식 텍스트 대비 경계값, 타깃 크기 24px 미만, hover 콘텐츠 닫기 수단 없음.

**피크 트래픽 관점**: 시즌 배너는 고채도 그라데이션·네온 색 위 작은 가격 문구가 많다. 시즌 모드에서는 프로모션 화면의 가격·조건 텍스트 대비 미달을 high로 본다.

**근거**: WCAG 2.2 SC 1.4.3 Contrast (Minimum)(AA), 1.4.11 Non-text Contrast(AA), 2.4.7 Focus Visible(AA), 1.4.4 Resize Text(AA), 1.4.10 Reflow(AA), 1.4.13 Content on Hover or Focus(AA), 2.5.8 Target Size (Minimum)(AA), 1.4.1 Use of Color(A).

## A11Y-07 반영된 접근성 수정의 회귀 금지

- **적용**: 클라이언트
- **왜 중요한가**: 외부 감사에서 지적받고 고친 항목이 다시 깨지면 감사 재지적·소송 시 "알고도 방치"가 된다. 편집기 저장, 라이브 환경 pull, 컴포넌트 사본 교체처럼 파일을 통째로 덮어쓰는 운영 방식이 있으면 회귀가 실수로 섞이기 쉽다.
- **판정 질문**:
  - 이 PR이 이미 반영된 접근성 수정(레포 프로파일의 보호 패턴, 감사 대응 커밋·이슈, 접근성 목적의 주석이 붙은 코드)을 삭제·약화·우회하는가?
  - 컴포넌트를 새 버전(`-v2`, 날짜 사본, 라이브 pull)으로 교체하면서 원본에 들어간 접근성 수정을 빠뜨렸는가?
  - 여러 레이아웃·진입점에 같은 접근성 수정이 있어야 하는데 한쪽만 바꿨는가?

**체크포인트**
- 보호 대상의 전형: `lang` fallback, 빈 `<title>` fallback, visually-hidden h1, 맥락 aria-label 보정, 장식 문자(이모지 등) 숨김, 헤딩 레벨 설정, 링크 접근 레이블 설정, 카드 접근 이름, 영상 aria-label·포스터·fallback alt. 레포 프로파일에 목록이 있으면 그것이 우선이다.
- 삭제 줄에 보호 패턴이 있으면 같은 PR의 추가 줄에 동등한 구현이 있는지 확인한다. 리포맷·이동이면 finding을 만들지 않는다.
- 대체 컴포넌트가 원본을 대체하는 경우를 본다(새 카드, 새 이미지+텍스트 블록, 공통 영상 컴포넌트 대신 직접 출력). 대체 컴포넌트에 같은 접근성 속성이 있어야 한다.
- 감사 대응 때 주석 처리하거나 걷어낸 방식을 되살리는 변경은 회귀다.
- 여러 레이아웃 간의 **기존** 불일치는 `pre-existing`이다. 이 PR이 새로 만드는 불일치만 본다.
- 미반영 감사 수정을 머지하는 PR은 `fixed`로 본다. 단, 같은 diff에 섞인 다른 변경(예: 라이브 스냅샷 차이)으로 다른 보호 패턴이 되돌아가지 않는지 확인한다.

**심각도 앵커**
- critical: 사용하지 않음. 핵심 흐름 불능 수준이면 A11Y-02·04로 간다.
- high: 전 페이지 수준의 보호 패턴(`lang` fallback, visually-hidden h1, 전역 보정 스크립트, 카드 접근 이름)을 대체 없이 제거. 또는 감사 지적으로 고친 컴포넌트를 수정 이전 버전으로 덮어씀.
- medium: 컴포넌트 수준 패턴(헤딩 레벨 설정, 링크 레이블 설정, 영상 aria-label) 제거, 레이아웃 한쪽만 고쳐 새 불일치 발생.
- low: 보호 패턴을 유지하되 약화. 예: 맥락 없는 aria-label로 단순화, fallback 제거.

**피크 트래픽 관점**: 시즌 직전에는 지난 시즌 컴포넌트를 복제해 재사용하기 쉽다. 그 사본은 감사 대응 이전 코드일 수 있다. 시즌 모드에서는 감사 대응 이전 사본으로 현재 컴포넌트를 대체하는 변경을 high로 본다.

**근거**: WCAG 2.2 Conformance(적합성은 전체 페이지·전체 과정 단위로 유지되어야 함) — https://www.w3.org/TR/WCAG22/#conformance . W3C WAI Evaluating Web Accessibility — https://www.w3.org/WAI/test-evaluate/ .

## A11Y-08 번역 경유·언어 리소스 동기화

- **적용**: 클라이언트
- **왜 중요한가**: 비영어 사용자에게 영어 문구가 섞이면 구매 안내(증정 조건, 품절, 오류)를 이해하지 못한다. 그 문구가 aria-label이면 스크린리더가 다른 언어로 읽는다.
- **판정 질문**:
  - 이 PR이 추가한 사용자 노출 문자열이 번역 함수·번역 키를 거치는가? 노출 문자열에는 본문, 버튼, aria-label, alt 기본값, 스크립트가 띄우는 메시지가 모두 포함된다.
  - 새 키가 기본 언어 파일과 레포가 지원하는 모든 언어 파일에 있는가?
  - 날짜·숫자·복수형을 locale 규칙(CLDR 복수형, locale 날짜 포맷)으로 처리하는가? 문자열 결합은 피한다.

**체크포인트**
- 스크립트 문자열은 서버·템플릿이 번역해 넘긴 문자열 사전을 참조한다. 스크립트 안의 `textContent = 'Added!'`, `` `Save ${n}%` `` 같은 하드코딩은 위반이다.
- HTML을 담는 번역 값은 레포 규약(예: HTML 허용 키 표시)을 따르고, 그렇지 않은 값은 escape한다.
- 컴포넌트 설정의 기본 텍스트는 편집기 기본값이다. 템플릿이 저장하는 설정 값에 들어가면 그대로 사용자에게 나가므로, 다국어 지역용 템플릿이면 번역 키나 지역별 설정으로 처리한다. 다국어 템플릿에 새로 들어간 고정 문구는 medium이다. 단일 언어 지역 전용 템플릿은 제외한다.
- 키 동기화는 번역 린트 도구(누락 키, 없는 키 참조)가 있으면 그 결과를 쓴다(`source: tool`). 없으면 diff로 직접 본다. 기본 언어 파일에 키를 추가했는데 같은 PR에서 다른 지원 언어 파일이 안 바뀌었는지가 대상이다. 기존 값의 오타 수정처럼 다른 언어 변경이 필요 없는 경우는 제외한다.
- 언어 파일이 번역 도구·편집기에 의해 덮어써지는 생성물이면, 키 이름 변경·삭제는 저장된 번역 값을 잃게 하므로 medium으로 본다.
- 레포 프로파일이 지원 언어 목록을 정하면 그 밖의 언어 누락은 감점하지 않는다.
- 지역별 사본 컴포넌트의 하드코딩 문구는 지역 단위 문구다. 비영어 locale로 열릴 수 있는 지역에 노출되는 새 컴포넌트면 medium, 단일 언어 지역 전용이면 low다. 브랜드·고유명사는 번역 대상이 아니다.

**심각도 앵커**
- critical: 사용하지 않음.
- high: 핵심 흐름의 문구(담기 버튼, 품절, 카트 오류, 결제 안내)를 하드코딩 문자열로 바꿈. 기존 번역 경유를 되돌림.
- medium: 새 사용자 노출 문자열·aria-label이 번역을 거치지 않음. 새 키가 지원 언어 파일에 없음. 존재하지 않는 키 참조. 키 이름 변경·삭제. 다국어 템플릿에 고정 문구.
- low: 단일 언어 지역 전용 컴포넌트의 하드코딩, 날짜·복수형 문자열 결합, 번역 값의 오역 의심.

**피크 트래픽 관점**: 시즌 문구는 짧은 기간에 대량으로 추가되고 번역이 늦게 따라온다. 시즌 모드에서는 비영어 지역에 노출되는 시즌 문구의 미번역을 medium으로 본다(low로 낮추지 않음).

**근거**: WCAG 2.2 SC 3.1.2 Language of Parts(AA, 번역 안 된 aria-label을 다른 언어 페이지에서 낭독). W3C Internationalization — https://www.w3.org/International/ . Unicode CLDR 복수형 규칙 — https://cldr.unicode.org/index/cldr-spec/plural-rules . ICU MessageFormat — https://unicode-org.github.io/icu/userguide/format_parse/messages/ .

## A11Y-09 지역별 가격·통화·프로모션·약관 노출 정확성

- **적용**: 클라이언트
- **왜 중요한가**: 영국 사용자에게 `$` 금액이, EU 사용자에게 미국 약관이, 서머타임 기간에 1시간 어긋난 마감 시각이 보이면 가격 표시 분쟁·환불 요구·소비자보호 이슈가 된다. 무료배송 기준 금액 하나를 환산 없이 모든 통화와 비교하면 지역마다 안내가 틀린다.
- **판정 질문**:
  - 이 PR이 표시하는 금액이 통화 포맷 기능으로 **현재 사용자의 표시(presentment) 통화**로 렌더되는가? 아니면 `$`/`£`/`€` 기호와 숫자가 하드코딩되거나 문자열로 결합되는가?
  - 프로모션 문구·증정 기준 금액·약관이 **그 지역에만** 노출되는가? 지역별 설정·국가 조건·숨김 규칙의 결과로 판단한다.
  - 카운트다운·마감 시각이 명시된 시간대로 정확히 계산되는가? 서머타임·사용자 현지 시각을 고려해야 한다.

**체크포인트**
- 금액은 금액 객체와 통화 포맷 함수(locale·통화 코드를 받는 포맷터)로만 표시한다. 가격·카트 합계는 표시 통화 기준 값을 쓴다. 상점 기준 통화 값과 표시 통화 값을 섞어 비교·표시하지 않는다.
- 고정 기준 금액(무료배송·증정 기준)은 지역별 값이 필요하다. 방법은 지역별 설정, 지역 메타데이터, 또는 근거 있는 환율 환산이다. 이 계산을 바꾸거나 새 기준 금액을 추가하는 PR은 지역별 값을 두는지 본다.
- 최소 화폐 단위(센트) 값을 정수 나눗셈으로 다루면 진행률·금액이 잘린다. 새로 쓰면 low다.
- 하드코딩 금액 문구는 두 가지로 판정한다.
  - 컴포넌트의 지역 표시와 노출 조건이 그 통화의 지역과 맞는가. 같은 기호를 여러 통화가 쓰면(`$` = USD·CAD·AUD·SGD) 통화 코드를 함께 적는다.
  - 같은 프로모션의 지역별 사본끼리 기준 금액이 의도대로 다른가.
- 약관: 새 약관 분기가 대상 국가를 정확히 나누는지, 국가 집합 정의가 여러 곳에서 어긋나지 않는지, fallback이 빈 약관이 되지 않는지 본다.
- 지역별 숨김: 새 페이지 템플릿·레이아웃이 공통 숨김 판정을 우회하면 안 된다(별도 레이아웃, 본문 직접 출력). 숨겨야 할 국가에 노출되면 high다.
- 카운트다운·마감 시각:
  - 고정 UTC 오프셋(예: PST = UTC-8 고정)은 서머타임 기간에 1시간 틀린다. IANA 시간대 이름이나 서버가 렌더한 오프셋 포함 ISO 8601 시각을 쓴다.
  - 약관의 마감 표기와 실제 카운트다운 기준 시각이 일치하는지 본다.
- 지역 분기 변수가 모든 경로에서 정의되는지 본다. 주석·조건 안에서만 정의되어 비어 있으면 모든 분기가 fallback으로 떨어진다.
- 하드코딩 할인 문구("20% off")와 실제 할인 설정의 불일치를 본다. 할인 설정이 코드 밖이면 diff만으로는 `possible`이다.

**심각도 앵커**
- critical: 모든 지역의 상품 화면 또는 카트에서 **실제 청구 통화·금액과 다른 금액**을 표시. 예: 가격을 통화 포맷 대신 한 통화 숫자로 하드코딩해 전 지역에 노출.
- high:
  - 특정 지역에 다른 통화 기호·금액의 프로모션·증정 기준 노출(예: 파운드 지역에 달러 기준 금액)
  - 지역에 맞지 않는 약관 노출 또는 약관 누락
  - 숨김 규칙 우회로 숨겨야 할 국가에 노출
  - 무료배송·증정 기준 계산을 바꿔 특정 통화에서 기준이 틀림
  - 카운트다운 마감이 약관과 다름(서머타임 포함)
- medium: 새 하드코딩 금액 문구가 지역과 맞지만 가격 변경 시 불일치 위험, 통화 코드 없는 `$`가 USD 외 달러 지역에 노출, 기준 금액 정수 나눗셈의 영향이 표시에 드러남.
- low: 단일 지역 전용 컴포넌트의 하드코딩 금액(지역 표시·노출 조건 일치), 금액 표기 형식 불일치(천 단위 구분 등).

**피크 트래픽 관점**: 대형 할인 시즌은 지역별 할인율·증정 기준·마감 시각이 가장 많이, 가장 짧은 주기로 바뀌는 시기이고 트래픽도 평시보다 훨씬 많아 잘못된 금액·약관 노출의 피해가 커진다. 북반구 서머타임 종료(EU·영국 10월 마지막 일요일, 미국 11월 첫 일요일)가 시즌과 겹친다. 시즌 모드에서는 카운트다운 시간대 오류를 high로 본다.

**근거**: ISO 4217 통화 코드 — https://www.iso.org/iso-4217-currency-codes.html . Unicode CLDR 통화·숫자 포맷 — https://cldr.unicode.org/ . ECMA-402 `Intl.NumberFormat`(통화 포맷)·`Intl.DateTimeFormat`(시간대) — https://tc39.es/ecma402/ . IANA Time Zone Database — https://www.iana.org/time-zones . ISO 8601 날짜·시각 표기.
