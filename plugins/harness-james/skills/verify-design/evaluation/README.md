# 설계 검증 루브릭 (design-verify) — 0.2.1 (2026-10-16)

> 요약 — 0.2.1(0.2.0 보정 결과·결정 6건 + 0.2.1 결정 2건). 플러그인에는 판정 기준(이 폴더)만 들어 있고, 프로파일·보고서·보정 기록은 각 프로젝트(기본 `docs/evaluation/design/`)에 둔다.
1. **11차원 59기준**: CON 7 · TRC 5 · REQ 5 · DEC 5 · EVD 6 · BEH 8 · FLR 5 · QAS 4 · THR 4 · RUN 4 · BND 6. `/verify` 코드와 안 겹친다. 기준 본문은 0.1.x에서 바뀌지 않았다.
2. refs 후보 60개 → 53개 유지·합침 + 6개 신설(EVD-01 출처 위계, EVD-05 수치 근거, EVD-06, CON-07, BEH-08, THR-04). TRC-03 필요성(제거 시험)이 refs TRC-03(고아)을 흡수했다. 변경표는 3장.
3. S를 쓰는 22개 기준에 `스크립트 추출 대상`을 적었다. 기준마다 `범위`(절 14 · 문서 20 · 묶음 25)를 두어 바뀐 곳만 다시 검증한다.
4. 판정은 REVISE / REVIEW_REQUIRED / PROCEED, **기준 위험도만** 쓴다(차원 점수 없음). 반증은 **critical·high 전부, 최대 8**(`limits.refute`), 순서는 심각도 → 확신 낮은 것(possible → likely → confirmed) → R(c). 상한 밖은 `uncertain` → REVIEW_REQUIRED.
5. **level = 사용 시점**: light = 문서를 고칠 때마다(S만, 판정 없음) · standard = 설계 중간 확인(기본, Fable 5.1 1회) · deep = 구현 시작 직전·설계 확정 때(Opus 5.5 관점별). traits에 irreversible-effects·data-migration이 있으면 리포트에 "deep 권장" 한 줄(자동 전환 없음). "분량 문턱 미정" 문구는 없앴다.
6. 보정 근거(보정 1회 기록, 플러그인에는 넣지 않음): deep이 standard보다 더 잡은 결함은 대부분 운영자·공격자 관점이었다.
7. **출력 요건(신설)**: 판정 출력은 light 구체 후보마다 채택(finding ID) 또는 기각(이유)을 적는다. 빠지면 평가 불완전 **경고**(판정은 그대로). 집계는 반대 방향 권고 짝을 드러낸다(`conflicts_with`, 권고 충돌 표). 둘 다 작업 순서 지시가 아니다.
8. **의도적 제외**(`exclude`·`readable:false`)는 미평가가 아니다("제외 문서"). 미독은 어느 관점도 읽지 않은 문서만 센다. 미독이 원자료(`source-material`·`review-input`)뿐이면 REVIEW_REQUIRED + "원자료 미독", 정본 문서 미독이면 REVISE(재실행).
9. 비용(framework 8.4)은 판정·반증을 나눈다. 판정 1k 토큰당 standard 0.092달러·deep 0.104달러(반증 몫 제외, ±25%). 반증은 건수 × 단가(Opus 0.20달러·Fable 1.23달러), 범위 0건 ~ `limits.refute`.
10. 과잉 지적 방지: 모든 finding이 `touches`(원 요구·불변식·원칙)를 가져야 한다. 상한은 전체 50, 기준당 5, low·info 10. 권고는 최소 변경이다.
11. 커버리지: C01–C13 모두 주 기준이 있다. C01·C03의 참·거짓은 X·H로만 정해진다. 관점 매핑은 4장.
12. 읽기 전용: 판정·반증 에이전트는 읽기 도구만 쓰고 결과를 반환한다. 보고서·findings 파일은 호출한 쪽이 쓴다(framework 7.3).
13. BND-06은 남기되 상한 low, 판정 제외. 예시 프로파일: level `standard`(deep 권장 대상), `limits.refute` 8, 원 요구 절 제목 실제 제목, `ref_only`, `compare_keys`.
14. 스킬 쪽 맞출 것: 구체 후보 처리표·권고 충돌 표 출력, 제외 문서 분리, 미독 합집합 기준, 반증 순서·상한 8, 비용 계수. 미확인: 프로파일 외부 URL(`verified:false`).

## 2. 판정 체계 한눈에

- 심각도 critical 60 · high 30 · medium 12 · low 4 · info 0. 신뢰도 confirmed 1.0 · likely 0.7 · possible 0.4 (`/verify`와 같음).
- 기준 위험도 `R(c) = min(100, w × Σ 심각도 × 신뢰도)`.
- **REVISE**: critical(confirmed·likely) 또는 평가 불완전. **REVIEW_REQUIRED**: `R(c) ≥ 임계값`, 반증 uncertain인 high+, 열린 X·H 확인이 걸린 high+, 원자료 미독. **PROCEED**: 그 밖.
- 차원 품질 점수는 없다(보정 시험 뒤 재검토). BND-06은 판정에서 빠진다(상한 low).
- 반증: critical·high 전부, 최대 8건(`limits.refute`), 순서는 심각도 → 확신 낮은 것 → R(c). 상한 밖은 `uncertain`으로 REVIEW_REQUIRED. REVISE(평가 불완전)는 기준 미평가·에이전트 실패 같은 실제 누락에만. 의도적 제외는 미평가가 아니다(framework 8.1·8.3).
- 출력 요건: 구체 후보 처리표(빠지면 평가 불완전 경고), 권고 충돌 표(framework 7.4·7.5).
- 읽기 전용: 판정·반증 에이전트는 읽기 도구만, 결과는 반환값으로. 보고서·findings 파일은 호출한 쪽이 쓴다(framework 7.3).
- level: `light`(문서를 고칠 때마다, S만, 판정 없음) · `standard`(설계 중간 확인, 기본, Fable 5.1 1회) · `deep`(구현 시작 직전·설계 확정 때, Opus 5.5 관점별). irreversible-effects·data-migration이면 리포트에 'deep 권장'. framework 8.2.
- 변경 상태 `scope_state`: changed / carried / resolved. 증분 검증에서는 carried를 참고로만 보인다.

### TRC-03과 refs TRC-03(고아)의 관계 (보정 a)

- 고아 검사: "이 요소가 요구 ID를 인용하는가" — 기계 검사, 싸다.
- 제거 시험: "인용한 요구가 원 요구인가, 빼면 그 원 요구 문장이 실제로 깨지는가" — 판단, 비싸다.
- 고아는 제거 시험에서 "인용 0건"인 하위 경우다. 둘을 따로 두면 같은 요소가 두 기준에 올라 중복 금지 규칙과 부딪힌다. 그래서 한 기준(TRC-03)에 두고, 고아는 스크립트 추출 대상으로만 남겼다.

## 5. 결함 범주 C01–C13 → 기준 커버리지

범주 정의는 설계 결함 이력(플러그인에 넣지 않음)에서 왔다.

| 범주 | 주 기준 | 보조 기준 | 한계 |
|---|---|---|---|
| C01 미확인 가정 단정 | EVD-02 | EVD-03, EVD-04, EVD-06, DEC-03 | 참·거짓은 X·H만. 루브릭은 출처·표지 유무를 판정 |
| C02 2차 대 1차 | EVD-01 | EVD-05(외부 한도 값) | 1차 출처가 아예 없으면 EVD-04로 넘어감 |
| C03 실행 환경 전제 | EVD-06 | EVD-04 | 실행(X)으로만 확정. 프로젝트 고유 사실(B-3)은 프로파일 `extra_questions` |
| C04 코드·기준선 | BND-02 | RUN-02, BEH-08 | 최신 여부는 X(원격 조회) |
| C05 결정 미전파 | CON-05 | CON-01·02·03·04·06, BND-01, DEC-04 | — |
| C06 낡은 문장·참조 | BND-03 | CON-05, DEC-04, BND-02 | — |
| C07 내부 모순 | CON-07 | CON-02, QAS-04 | — |
| C08 ID·번호·수치 인용 | BND-04 | CON-07 | "어느 체계를 뜻했나"는 L |
| C09 과설계·범위 확대 | TRC-03 | TRC-04, DEC-01, DEC-02, BND-06 | 최종 범위 결정은 H. 루브릭은 후보와 근거 사슬까지 |
| C10 근거 없는 수치 | EVD-05 | QAS-02, FLR-03 | 측정 자체는 X |
| C11 상태·전이·제약 누락 | BEH-08 | BEH-01~07, TRC-01, REQ-02·04, FLR 전부, DEC-05 | 깊은 인터리빙은 도구 필요(BEH-04 표시까지) |
| C12 검증·관측 불가 | RUN-04 | TRC-02, REQ-03·05, QAS-01, THR-03 | 거짓 통과의 실제 발생은 실행으로 확인 |
| C13 모호한 용어 | CON-01 | REQ-01, BND-05 | — |

- 못 잡는 범주는 없다. 다만 C01·C03·C04는 참·거짓 또는 최신 여부가 외부 확인(X)에 달려 있어, 루브릭 판정은 `possible`·`likely`에 머무는 경우가 많다.
- 작성 과정 결함(병렬 세션 충돌, 미커밋 교정 등)은 문서 내용이 아니라서 범위 밖이다. 결과로 문서에 남은 불일치만 CON·BND가 잡는다.
- 보정 시험은 아직 고치지 않은 결함 표본으로 하는 것이 현실적이다. 정답은 rubric에 쓰지 않았다.
