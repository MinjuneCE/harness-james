# BND — 묶음 위생

- 버전: 0.1.1 (2026-10-16)
- 적용: 여러 문서·여러 세션이 쓴 묶음 (BND-05·06은 공통 또는 agent-authored)
- 보는 것: 주제마다 정본이 하나인가, 근거로 든 시점이 고정되고 최신인가, 참조가 살아 있는가, ID·번호 체계가 하나인가, 구현자가 추측 없이 따를 수 있는가, 분량이 변경에 비례하는가.
- 보지 않는 것:
  - 사본 사이에 값이 실제로 다른가 → **CON-02** (정본이 없다는 사실은 BND-01)
  - 결정 상태·대체 표시 → **DEC-04**
  - 결정 미반영 → **CON-05**

이 차원의 기준은 대부분 스크립트 추출 대상이 있다. 값싼 결함이다.

## BND-01 정본 지정

- **적용**: multi-doc, agent-authored · **범위**: 묶음
- **왜 중요한가**: 같은 결정·표를 여러 문서에 두면 사본이 따로 진화한다. 결정이 바뀔 때마다 사본 수만큼 비용이 든다.
- **판정 질문**
  - 각 주제(결정·상태표·설정값·가정 목록)의 정본 문서가 정해져 있는가?
  - 다른 문서는 정본을 복사하지 않고 참조하는가(요약이면 정본 위치를 적는가)?

**체크포인트**
- 같은 표·같은 문단이 여러 문서에 있는가.
- 묶음 경계를 넘는 규칙(예: 설계 문서와 시나리오 문서)에서 원본이 어느 쪽인가 적혔는가.
- 프로파일 `bundle`의 문서 역할과 실제 내용이 맞는가.

**검사 방법**: S+L
- **스크립트 추출 대상**: 중복 내용(같은 표 머리, 높은 유사도의 문단·행), 문서별 결정 ID 정의 위치(정의가 둘 이상인 ID).

**심각도 앵커**
- high: 핵심 결정·상태표가 정본 없이 둘 이상에 정의돼 있고 이미 값이 갈림(CON과 함께)
- medium: 정본 없는 사본(아직 값은 같음)
- low: 요약이 정본 위치를 적지 않음

**근거 요구**: 사본 위치 둘 이상 인용.

**잡는 결함 범주**: C05
**근거 출처**: SK-AN(B) A 중복

## BND-02 기준 시점 고정

- **적용**: multi-doc, agent-authored · **범위**: 묶음
- **왜 중요한가**: 근거로 든 코드·문서 시점이 고정되지 않았거나 낡으면 줄 번호·"현재와 차이"·결함 판정이 통째로 틀린다.
- **판정 질문**
  - 근거로 든 코드·외부 문서·다른 묶음의 시점이 고정(커밋·버전·날짜)돼 있는가?
  - 같은 대상의 기준 시점이 묶음 안에서 하나인가?
  - 그 시점이 검증 시점의 최신과 같은가(다르면 차이가 적혔는가)?

**체크포인트**
- 문서마다 인용한 커밋 식별자·버전.
- 다른 문서 버전에 기댄 문서(예: 옛 버전 명세 기반 계획).
- 최신 여부는 외부 조회(X)로만 확정된다. 묶음 안 불일치는 조회 없이 확정된다.

**검사 방법**: S+X
- **스크립트 추출 대상**: 커밋 식별자(16진 7–40자), 버전 표기(vN.N), 기준 날짜와 각 위치. 같은 대상(레포·문서)에 대해 다른 값이 나오는 목록. 프로파일 `baseline`이 있으면 그 값과 비교.

**심각도 앵커**
- high: 판정·작업이 낡은 기준 시점 위에 서 있고 그 시점 이후 바뀐 내용이 결론을 바꿈
- medium: 같은 대상의 기준 시점이 문서마다 다름
- low: 기준 시점 표기 없음(내용은 최신과 같음)

**근거 요구**: 시점 표기 위치 인용 + 비교 대상(다른 문서 값 또는 조회 결과).

**잡는 결함 범주**: C04, C06
**근거 출처**: ADR(A) supersede, SK-CONST(B) 개정 이력

## BND-03 깨진·낡은 참조

- **적용**: multi-doc · **범위**: 묶음
- **왜 중요한가**: 삭제·개명 뒤 남은 참조, 상황이 바뀐 뒤 남은 "아직·지금은" 문장은 독자를 옛 상태로 보낸다.
- **판정 질문**
  - 존재하지 않는 ID·절·파일을 가리키는 참조가 없는가?
  - 병합·삭제된 ID가 살아 있는 맥락으로 참조되지 않는가?
  - 진행 상태를 말하는 문장(수집 중·아직·예정)이 지금도 맞는가?

**체크포인트**
- 링크·앵커, ID 참조, 병합·삭제 ID 목록과 참조.
- 시간 표현("지금은·아직·곧·이번 주") 문장.

**검사 방법**: S+L
- **스크립트 추출 대상**: 링크·앵커 대상 존재 여부, ID 참조 대 정의 차집합, 병합·삭제 표시된 ID의 참조 위치, 시간 표현 문장 목록.

**심각도 앵커**
- medium: 낡은 참조·문장이 구현·검증 대상을 잘못 가리킴
- low: 깨진 링크, 낡은 진행 상태 문장

**근거 요구**: 참조 인용 + 대상이 없다는 추출 결과.

**잡는 결함 범주**: C06
**근거 출처**: SK-CL(B) 추적 참조

## BND-04 ID·번호 체계

- **적용**: multi-doc · **범위**: 묶음
- **왜 중요한가**: ID가 없으면 추적·검증이 안 된다. 한 문서 안에 번호 체계가 둘이면 "결정 N"이 무엇을 뜻하는지 문서마다 달라진다. ID가 다른 묶음과 겹치면 결함·작업이 섞인다.
- **판정 질문**
  - 각 요구·결정·가정·시나리오·작업이 안정된 ID를 갖는가?
  - 한 문서 안의 번호 체계가 하나인가(둘이면 인용 때 구분 표기가 정해졌는가)?
  - 개수·범위 표기가 실제와 같고, ID가 다른 묶음과 겹치지 않는가?

**체크포인트**
- 프로파일 `id_patterns`에 맞는 ID 형식.
- 같은 문서의 요약 번호와 본문 번호.
- ID 중복, 재사용, 건너뜀.

**검사 방법**: S+L
- **스크립트 추출 대상**: `id_patterns`별 ID 정의·인용, 중복 정의, 한 문서 안의 서로 다른 번호 목록(요약 번호, 본문 번호), 개수 재계산. LLM은 "어느 체계를 뜻했나"만 판단한다.

**심각도 앵커**
- high: 같은 번호가 두 결정을 가리켜 인용한 문서가 서로 다른 결정을 따름
- medium: 번호 체계 혼용, ID 충돌, 핵심 항목 ID 없음
- low: 개수 오기, 번호 없는 부가 문단

**근거 요구**: ID 정의·인용 위치 인용과 추출 결과 행.

**잡는 결함 범주**: C08
**근거 출처**: SK-CL(B) 80% 추적 참조 규칙, ADR(A) 번호 (refs TRC-05 흡수)

## BND-05 구현 가능성

- **적용**: agent-authored · **범위**: 문서
- **왜 중요한가**: 구현 에이전트가 추측해야 하는 문서는 스펙을 무시하거나 기존 요소를 중복으로 만든다.
- **판정 질문**
  - 구현 에이전트가 추측 없이 따를 수 있을 만큼 구체적인가(바꿀 곳, 재사용할 기존 요소, 바꾸지 말 것)?

**체크포인트**
- "기존 서비스를 활용" 같은 지시에 대상이 특정됐는가.
- 걷어낼 것과 남길 것의 목록.
- 작업마다 완료 조건.

**검사 방법**: L

**심각도 앵커**
- medium: 핵심 작업의 대상·경계가 모호해 중복 구현 여지
- low: 부가 작업의 모호

**근거 요구**: 작업·지시 인용.

**잡는 결함 범주**: C11, C13
**근거 출처**: BMAD(B) §9, BOCKELER(A), CC-BP(A) (refs BND-04)

## BND-06 분량 비례

- **적용**: 공통 · **범위**: 묶음
- **왜 중요한가**: 변경 크기에 비해 장황한 문서는 리뷰가 생략된다. 반복이 많으면 사본 불일치가 생긴다.
- **판정 질문**
  - 문서 분량·절차가 변경 크기와 모호성에 비례하는가?
  - 같은 내용을 여러 번 반복하지 않는가?

**체크포인트**
- 요약만 읽어도 결론이 서는가.
- 작은 변경에 과잉 절(수용 기준 수, 표 수).

**검사 방법**: L+H

**심각도 앵커** (상한 low)
- low: 과잉 분량·반복
- info: 리뷰 부담에 대한 참고
- 이 기준의 finding은 판정(REVISE·REVIEW_REQUIRED)에 들어가지 않는다. 리포트에 참고로만 보인다(framework 8장).

**근거 요구**: 반복 위치 또는 분량 지표(절 수·줄 수).

**잡는 결함 범주**: C09
**근거 출처**: BOCKELER(A), RADAR(A), UBL(A) (refs SCP-02)
