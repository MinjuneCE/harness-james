# EVD — 근거·가정

- 버전: 0.1.0 (2026-10-16)
- 적용: 모든 설계 묶음 (EVD-02는 external-integration)
- 보는 것: 설계가 기대는 사실의 출처 등급과 출처끼리의 충돌 처리, 외부 동작 주장의 근거, 숨은 가정, 미확인 항목의 처리, 수치의 근거, 실행 환경 전제.
- 보지 않는 것:
  - 외부 사실의 참·거짓 자체 → 외부 조회(X)·사람(H). 이 차원은 "출처가 붙었나, 표시됐나"를 본다
  - 같은 값이 문서마다 같은가 → **CON-02** (값의 근거는 EVD-05)
  - 결정의 대안·가역성 → **DEC**
  - 근거로 든 코드·문서 시점 → **BND-02**

**출처 등급** (이 차원 공통)
- 1차: 공식 문서, 당사자의 답(서면), 실측 데이터·실행 결과, 코드(우리 시스템의 동작에 한함)
- 2차: 회의 발언, 기억, 다른 대상을 위한 지침의 전용, 추측, 다른 문서의 요약
- 외부 시스템마다 무엇이 1차인지는 프로파일 `external_sources`가 정한다.

## EVD-01 출처 위계

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 2차 진술(회의·기억·추측)로 규칙을 세우면, 1차 출처가 나왔을 때 설계가 통째로 뒤집힌다. 충돌을 숨기면 같은 오류가 다른 이름으로 되살아난다.
- **판정 질문**
  - 같은 사실에 1차 출처와 2차 진술이 함께 있고 서로 다르면, 설계가 1차를 따르는가?
  - 그 충돌이 문서에 드러나 있는가(무엇이 어떻게 달랐고 왜 1차를 택했나)?
  - 설계 규칙의 근거가 2차 진술뿐이면, 같은 사실의 1차 출처를 찾아본 기록이 있는가?

**체크포인트**
- 규칙·판정 조건의 근거 표기(출처 종류).
- 다른 대상을 위한 지침을 이 대상의 동작으로 옮긴 추론(예: 한 주체에게 준 지침을 다른 주체의 동작으로 봄).
- 1차 출처가 나온 뒤에도 2차 진술에 기댄 문장이 남았는가.
- 우리 시스템의 동작은 코드(고정된 시점)가 1차다. 외부 시스템의 동작은 그 시스템의 공식 문서·당사자 답이 1차다.

**검사 방법**: L+X
- 보조로 S(근거 표기 없는 판정 규칙 문장, "회의·발언·들었다" 같은 2차 표지 문장 추출)를 쓸 수 있다.

**심각도 앵커**
- critical: 비가역 부작용을 정하는 규칙이 1차 출처와 충돌하는 2차 진술에 기댐
- high: 판정 규칙이 1차 출처와 충돌하는 2차 진술에 기대거나, 충돌을 알면서 드러내지 않음
- medium: 규칙의 근거가 2차뿐이고 1차를 찾아본 기록이 없음
- low: 충돌을 드러냈으나 어느 쪽을 택했는지 이유 없음

**근거 요구**: 2차 진술 위치 인용 + 1차 출처 위치(문서 위치 또는 외부 링크). 1차를 못 찾았으면 찾아본 곳(부재형)과 `possible`.

**잡는 결함 범주**: C02
**근거 출처**: HALL(A) 주장마다 인용, SK-CL(B) 환각 금지, ATAM(A) risk. 원칙 자체는 범용(refs B.2는 프로젝트 고유로 분류했으나 메인 세션 보정으로 핵심 기준이 됨)

## EVD-02 외부 동작 주장의 근거

- **적용**: external-integration, agent-authored · **범위**: 절
- **왜 중요한가**: 확인하지 않은 외부 동작을 단정문으로 쓰면 그 위에 상태·정책·검증이 쌓인다. 가정 하나가 여러 문서를 여러 버전에 걸쳐 흔든다. 지운 가정이 다른 이름으로 되살아나기도 한다.
- **판정 질문**
  - 주어가 우리 밖의 시스템·주체인 문장(그것이 ~한다)마다 1차 출처가 붙었거나 미확인·추정·진술 표지가 있는가?
  - 표지 없는 단정이 설계 규칙의 근거로 쓰이지 않는가?

**체크포인트**
- 외부 시스템의 상태 값, 이벤트 순서·중복, 멱등 보장, 한도·오류 형태, 처리 시간.
- 외부 사람·팀의 업무 방식(무엇을 보고 무엇을 가져가는가).
- 데이터 해석: 표본이 0이거나 조건이 다른 데이터로 일반 주장을 함.
- 확인 안 된 사실을 확정형으로 쓴 문장(AI 다세션 작성에서 흔함).
- 한 번 지운 가정이 다른 문장·다른 ID로 다시 들어왔는가.

**검사 방법**: S+L+X
- **스크립트 추출 대상**: 외부 주체 이름(프로파일 `external_sources`의 시스템 목록)이 주어인 문장 중 출처 링크·표지(미확인·추정·진술·해석 등, 프로파일이 정함)가 없는 문장과 위치.

**심각도 앵커**
- critical: 비가역 부작용이 근거 없는 외부 동작 단정에 기댐
- high: 판정 규칙·상태 정책이 근거 없는 외부 동작 단정에 기댐
- medium: 근거 없는 단정이 있으나 설계 규칙에 쓰이지 않음, 또는 데이터 해석의 모집단 오류
- low: 표지는 있으나 표지 종류(미확인·추정·진술)가 틀림

**근거 요구**: 단정문 인용 + 그 문장을 근거로 쓰는 설계 위치. 외부 사실 판정에는 외부 출처 링크, 없으면 `possible` 이하.

**잡는 결함 범주**: C01
**근거 출처**: HALL(A), SK-CL(B) "do NOT hallucinate", refs BND-05 근거 없는 확신 흡수

## EVD-03 가정 목록화

- **적용**: 공통 · **범위**: 묶음
- **왜 중요한가**: 숨은 가정은 확인 대상이 되지 않는다. 깨지면 어디가 무너지는지 아무도 모른다.
- **판정 질문**
  - 설계가 기대는 가정이 목록(ID 포함)으로 있는가?
  - 각 가정에 확인됨·미확인·사용자 진술 같은 상태가 있는가?
  - 시나리오·규칙이 기대는 외부 전제가 그 목록에 있는가?

**체크포인트**
- 가정 목록과 본문 단정문(EVD-02 추출)의 대응.
- 가정을 지울 때 그 가정에 기대던 규칙·시나리오도 정리됐는가(아니면 CON-05).

**검사 방법**: L

**심각도 앵커**
- high: 핵심 흐름이 목록에 없는 가정에 기댐
- medium: 가정 목록에 상태 표시 없음
- low: 부가 흐름의 가정 누락

**근거 요구**: 가정에 기대는 본문 인용 + 가정 목록에서 찾아본 결과.

**잡는 결함 범주**: C01
**근거 출처**: SK-CL(B) [Assumption], ATAM(A) risk

## EVD-04 미확인 항목·위험 처리

- **적용**: 공통 · **범위**: 묶음
- **왜 중요한가**: "확인 필요"만 적은 항목은 설계 확정 뒤 방치된다. 틀렸을 때 무엇이 무너지는지 모르면 확인 우선순위를 정할 수 없다.
- **판정 질문**
  - 미확인 가정·외부 확인 항목마다 담당(또는 상대), 확인 방법, 틀렸을 때 영향이 적혔는가?
  - 식별한 위험과 의도적으로 받아들인 비위험이 구분돼 있는가?

**체크포인트**
- 외부 확인 목록(누구에게 무엇을 묻는가)이 한 곳에 모였는가.
- 틀렸을 때 영향이 큰 항목에 대체안·중단 조건이 있는가.
- 실행 환경 전제(EVD-06)도 이 목록에 있는가.

**검사 방법**: S+L
- **스크립트 추출 대상**: 미확인·확인 필요 표지가 붙은 항목과 각 항목의 담당·방법·영향 필드 유무.

**심각도 앵커**
- high: 틀리면 설계가 무너지는 항목에 영향·담당 없음
- medium: 미확인 항목에 확인 방법·담당 없음
- low: 위험·비위험 구분 없음

**근거 요구**: 미확인 항목 인용.

**잡는 결함 범주**: C01, C03
**근거 출처**: ATAM(A) risk·non-risk, BASS-ATAM(A), PREMORTEM(A·부분), RUST(B) unresolved questions

## EVD-05 수치 근거

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 시간·한도·임계값이 근거 없이 정해지면 너무 짧거나 길어 실패하고, 바꿀 때 무엇을 다시 봐야 하는지 모른다.
- **판정 질문**
  - 시간·한도·임계값·주기·재시도 횟수마다 근거(측정, 문서, 담당자가 있는 명시적 결정)가 있거나, 가정으로 표시돼 있는가?
  - 외부 시스템의 한도·대기 시간과 맞물리는 값이 그 시스템의 1차 출처 값과 모순되지 않는가?

**체크포인트**
- 설정 값, 상한, 주기, 타임아웃, 재시도 횟수, 보존 기간, 사용자에게 약속한 시간.
- 파생 값(최대 지연 = 주기 + 지연 등)의 계산.
- 값이 바뀐 이력이 있으면 바뀐 근거.

**검사 방법**: S+L
- **스크립트 추출 대상**: 숫자 + 단위, 기간 표기, 설정 키 = 값 쌍과 같은 문장·인접 문장의 근거 표지(출처 링크, 측정, 결정 ID, "가정·추정" 표지).

**심각도 앵커**
- high: 외부 한도·대기 시간과 모순되는 값, 또는 돈·데이터에 닿는 값이 근거도 가정 표시도 없음
- medium: 핵심 값이 근거 없이 가정 표시만 있고 검증 계획 없음
- low: 보조 값의 근거 없음

**근거 요구**: 값 인용 + 근거를 찾아본 곳. 외부 값과 모순이면 1차 출처 위치.

**잡는 결함 범주**: C10
**근거 출처**: SRE-LAUNCH(A) capacity, WA-REL(A) "용량 추측 금지", BL-TIMEOUT(A)

## EVD-06 실행 환경 전제

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 환경·도구·데이터가 문서대로라고 가정한 설계는 첫 실행에서 무너진다. 실행 한 번이면 드러나는 것을 설계가 사실로 적는다.
- **판정 질문**
  - 설계·검증 계획이 기대는 환경 전제(테스트 데이터 존재, 도구 동작, 접근 권한, 설치된 구성 요소)가 실행·조회로 확인됐거나, 확인 목록(EVD-04)에 있는가?

**체크포인트**
- 검증 계획이 쓰는 데이터·계정·스텁이 실제로 있는가에 대한 진술.
- "도달 불가·없음·불가능" 같은 부정 단정의 근거(한 번 시도했는가).
- 환경이 바뀐 뒤(새 도구·새 데이터) 옛 전제 문장이 남았는가(남았으면 BND-03과 함께).

**검사 방법**: L+X
- 참·거짓은 실행(X)으로만 정해진다. 판정은 "확인됐다는 기록이 있나"를 본다.

**심각도 앵커**
- high: 검증·작업 계획 전체가 확인 안 된 환경 전제에 기댐
- medium: 일부 검증 항목이 확인 안 된 전제에 기댐
- low: 환경 서술이 낡음

**근거 요구**: 전제 문장 인용 + 확인 기록을 찾아본 곳.

**잡는 결함 범주**: C03, C01
**근거 출처**: SRE-LAUNCH(A) 외부 의존, WA-REL(A) 복구 절차 시험
