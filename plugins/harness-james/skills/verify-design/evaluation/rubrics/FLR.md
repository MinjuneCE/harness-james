# FLR — 실패·복구

- 버전: 0.1.0 (2026-10-16)
- 적용: 외부 연동·비동기·자동화 trait가 켜진 묶음 (FLR-04는 공통)
- 보는 것: 의존이 실패했을 때의 동작, 결과 불명의 확정 방법, 타임아웃·재시도·과부하 정책, 단계별 오류 처리, 자동 처리가 포기한 건의 사람 처리. 정책의 존재와 일관성을 본다.
- 보지 않는 것:
  - 코드가 정책대로 구현했는가 → `/verify` REL

  - 정책 값의 근거 → **EVD-05**, 값의 문서 간 일치 → **CON-02**
  - 실패를 알아채는 신호 → **RUN-04**

## FLR-01 의존별 실패 모드

- **적용**: external-integration · **범위**: 문서
- **왜 중요한가**: 외부 의존 하나의 장애가 전면 장애로 번진다. 평소 안 쓰는 대체 경로는 장애 때 실패한다.
- **판정 질문**
  - 각 외부 의존이 실패(오류·시간 초과·느림·없음·이벤트 미도착)했을 때의 동작이 정의됐는가?
  - 대체(폴백) 경로가 있다면 그 경로를 평소에도 실행하거나 검증하는 방법이 적혔는가?

**체크포인트**
- 의존 목록(호출·구독 대상)과 의존별 실패 동작 표.
- 이벤트 경로가 끊겼을 때 안전망(주기 조회 등)이 같은 결과를 내는가.
- 단일 장애점.

**검사 방법**: L

**심각도 앵커**
- critical: 의존 하나의 실패로 핵심 흐름 전면 중단, 대체 없음
- high: 핵심 의존의 실패 동작 미정, 또는 시험되지 않는 드문 대체 경로에 핵심 흐름이 기댐
- medium: 부가 의존의 실패 동작 미정

**근거 요구**: 의존 정의 인용 + 실패 동작을 찾아본 절.

**잡는 결함 범주**: C11
**근거 출처**: SRE-LAUNCH(A), YUAN(A), BL-FALLBACK(A) (refs FLR-05 흡수)

## FLR-02 결과 불명 처리

- **적용**: external-integration, irreversible-effects · **범위**: 문서
- **왜 중요한가**: 결과를 모를 때 비가역 호출을 다시 보내면 부작용이 두 번 난다. 실패로 확정해도 실제로 처리된 건을 놓친다.
- **판정 질문**
  - 호출 결과를 모를 때(시간 초과·연결 끊김·비동기 작업 미완료) 재실행이 아니라 조회·대조로 확정하는 경로가 있는가?
  - 결과 불명 건이 확정될 때까지 어떤 상태에 머물고, 그동안 다른 작업자가 재실행하지 않는가?

**체크포인트**
- 외부 작업 ID·참조값의 저장 시점.
- 조회로 확정할 수 없을 때(조회도 실패) 상한과 사람 처리.
- 레이트 리밋 거절을 미실행으로 볼 근거(외부 1차 출처).

**검사 방법**: L

**심각도 앵커**
- critical: 결과 불명에 비가역 호출 재실행 가능
- high: 결과 불명을 조회 없이 실패로 확정
- medium: 확정 상한·사람 처리 미정

**근거 요구**: 호출 흐름 인용 + 결과 불명 경로를 찾아본 절.

**잡는 결함 범주**: C11
**근거 출처**: BL-IDEM(A), BL-TIMEOUT(A)

## FLR-03 타임아웃·재시도·과부하

- **적용**: external-integration, async-events · **범위**: 문서
- **왜 중요한가**: 타임아웃이 없으면 무한 대기, 여러 층 재시도는 폭주, 회복 순간 밀린 작업이 몰리면 붕괴한다.
- **판정 질문**
  - 원격 호출마다 타임아웃, 재시도 상한, 지터 있는 지수 백오프가 정해졌고, 재시도는 한 층에서만 하는가?
  - 밀린 작업(백로그)의 상한·처리 속도 제한이 있고, 회복 때 한꺼번에 몰리는 것을 다루는가?

**체크포인트**
- 클라이언트·작업자·스케줄러가 각각 재시도하는가(층 중복).
- 재시도할 오류와 하지 않을 오류의 구분(비멱등 호출 제외).
- 타임아웃이 외부 시스템의 최대 응답 시간보다 짧지 않은가(값의 근거는 EVD-05).
- 일괄 재처리의 속도 제한.

**검사 방법**: L+S
- **스크립트 추출 대상**: 타임아웃·재시도·백오프·주기 설정 키와 값, 설정이 붙은 호출·작업 이름.

**심각도 앵커**
- critical: 회복 경로가 부하를 키워 핵심 흐름 전면 장애로 이어짐
- high: 타임아웃 없음, 여러 층 재시도, 비멱등 호출에 재시도
- medium: 백오프·지터 없음, 백로그 상한 없음

**근거 요구**: 정책 위치 인용 또는 찾아본 곳.

**잡는 결함 범주**: C11, C10
**근거 출처**: BL-TIMEOUT(A), SRE-CASCADE(A), SRE-OVERLOAD(A), BL-QUEUE(A), AWS-PES-2011·2021(A) (refs FLR-04 흡수)

## FLR-04 오류 처리 경로

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 치명 장애 대부분은 비치명 오류를 무시·로그만·전체 중단으로 잘못 처리해서 생긴다.
- **판정 질문**
  - 단계별로 오류 종류(일시·영구·입력·권한)에 따른 처리(재시도·실패 확정·사용자 안내·사람 처리)가 설계에 있는가?
  - "실패 시 로그" 한 줄로 끝나는 처리가 없는가?

**체크포인트**
- 오류 분류표와 분류별 결과 상태·사유.
- 사용자에게 보이는 결과(화면·응답)와 내부 상태가 맞는가.

**검사 방법**: L

**심각도 앵커**
- high: 부작용 흐름의 오류가 무시·로그만으로 처리됨
- medium: 오류 분류 없음
- low: 부가 단계의 처리 미정

**근거 요구**: 오류 처리 절 인용 또는 찾아본 곳.

**잡는 결함 범주**: C11
**근거 출처**: YUAN(A) 92% (refs FLR-06)

## FLR-05 사람 개입 경로

- **적용**: state-machine, automation · **범위**: 문서
- **왜 중요한가**: 자동 처리가 포기한 건이 보이지 않게 쌓인다. 반대로 드문 예외마다 자동 장치를 만들면 과설계가 된다.
- **판정 질문**
  - 자동 처리가 포기한 건(상한 도달·재시도 소진·분류 불가)을 사람이 찾고 처리·재개하는 방법이 정해졌는가?
  - 사람이 처리한 뒤 시스템 상태가 어떻게 맞춰지는가가 정해졌는가?

**체크포인트**
- 사람이 찾는 수단(목록·알림·지표 중 하나면 충분).
- 운영자 조치 뒤 늦게 오는 이벤트의 처리(BEH-01).
- 이 경로가 원 요구에 있는가(없으면 TRC-03과 함께 본다).

**검사 방법**: L

**심각도 앵커**
- high: 포기한 건이 사용자 흐름을 막는데 사람이 찾을 수단이 없음
- medium: 사람 처리 뒤 상태 맞춤 방법 없음

**근거 요구**: 포기 지점 인용 + 사람 경로를 찾아본 절.

**잡는 결함 범주**: C11, C12
**근거 출처**: SRE-LAUNCH(A) manual processes, SRE-PRR(A) (refs FLR-07)
