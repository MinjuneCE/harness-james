# REQ — 요구 품질

- 버전: 0.1.0 (2026-10-16)
- 적용: 모든 설계 묶음
- 보는 것: 설계 요구 하나하나가 측정 가능하고, 하나만 말하고, 실패·이상 조건의 동작까지 말하고, 완료를 판정할 수 있는가. 미해결 자리표시가 남지 않았는가.
- 보지 않는 것:
  - 요구가 원 요구에 대응하는가, 필요한가 → **TRC**
  - 상태별 동작의 빈칸(상태×이벤트) → **BEH-01**
  - 숫자 값의 근거 → **EVD-05**
  - 미확인 가정의 처리 → **EVD-04** (자리표시가 "확인 필요"면 EVD-04, "TBD·미정"이면 REQ-02)

## REQ-01 모호어·측정 불가

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: "빠르게·안정적으로·적절히·즉시"는 검증할 수 없다. 구현자와 검증자가 서로 다른 기준을 쓴다.
- **판정 질문**
  - 정도·속도·빈도를 말하는 표현에 측정 기준(값·단위·조건)이 붙어 있는가?

**체크포인트**
- 형용사·부사로 된 품질 표현, "가능하면·필요시·등".
- 보안·정합성·성능 속성의 표현이 특히 중요하다.
- 사용자 화면 문구 요구는 문구 자체 또는 문구 키가 정해졌는가.

**검사 방법**: S+L
- **스크립트 추출 대상**: 모호어 목록(프로파일이 언어별로 더할 수 있음)이 나온 요구 문장과 위치. LLM은 측정 기준이 같은 문장·인접 문장에 있는지 판단한다.

**심각도 앵커**
- high: 보안·정합성·성능 속성이 측정 불가
- medium: 그 외 기능 요구의 측정 불가
- low: 설명 문장(요구 아님)의 모호어

**근거 요구**: 요구 문장 인용.

**잡는 결함 범주**: C13, C12
**근거 출처**: SK-AN(B) B, 29148(A·간접) Unambiguous·Verifiable

## REQ-02 미해결 자리표시

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 남은 TBD·미정은 구현자가 추측으로 채운다.
- **판정 질문**
  - TODO·TBD·???·미정 표시가 남아 있지 않은가? 남았다면 담당과 기한(또는 결정 항목 ID)이 붙었는가?

**체크포인트**
- 자리표시가 핵심 흐름에 있는가, 부가 항목에 있는가.
- 결정 대기 목록(결정 필요 표)에 올라 있는가.

**검사 방법**: S
- **스크립트 추출 대상**: 자리표시 토큰(TODO, TBD, ???, 미정, 추후, 나중에 등)과 위치, 같은 줄·절의 담당·기한·결정 ID 유무.

**심각도 앵커**
- high: 핵심 흐름의 미정이 담당·결정 항목 없이 남음
- medium: 핵심 흐름의 미정이 결정 항목으로 올라 있으나 기한·담당 없음
- low: 부가 항목의 미정

**근거 요구**: 자리표시 인용.

**잡는 결함 범주**: C11
**근거 출처**: SK-AN(B) B

## REQ-03 단일성·검증 가능성

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 여러 가지를 한 문장에 묶은 요구는 부분만 구현되고 통과로 보고된다.
- **판정 질문**
  - 각 요구가 한 가지를 말하는가?
  - 통과·실패를 판정할 수 있는가?

**체크포인트**
- "A 하고 B 하며 필요시 C" 꼴.
- 조건이 여럿인 요구는 조건별로 결과가 정해졌는가.

**검사 방법**: L

**심각도 앵커**
- high: 핵심 흐름 요구가 판정 불가
- medium: 복합 요구, 부가 요구의 판정 불가

**근거 요구**: 요구 문장 인용.

**잡는 결함 범주**: C12
**근거 출처**: 29148(A·간접) Singular·Verifiable

## REQ-04 원치 않는 동작 명세

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 정상 경로만 적은 요구는 실패·이상 경로를 구현자에게 맡긴다. 치명 장애 대부분은 비치명 오류의 잘못된 처리에서 나온다.
- **판정 질문**
  - 정상 동작 요구마다 "만약 <실패·이상 조건>이면 시스템은 …" 형태의 동작이 있는가?
  - 사용자에게 보이는 흐름이면 실패 시 사용자에게 무엇이 보이는가가 정해졌는가?

**체크포인트**
- 입력 오류, 외부 실패·시간 초과, 중복 요청, 권한 없음, 이미 끝난 대상에 대한 요청.
- 결과가 확정되지 않았을 때 사용자 화면 상태.

**검사 방법**: L

**심각도 앵커**
- high: 외부 실패·시간 초과 시 동작이 미정이고 그 흐름에 부작용이 있음
- medium: 입력·권한 이상 조건의 동작 미정, 실패 시 사용자 화면 미정
- low: 드문 이상 조건 일부 누락(문서가 범위 밖으로 표시하지 않음)

**근거 요구**: 정상 요구 인용 + 이상 조건 동작을 찾아본 절(부재형).

**잡는 결함 범주**: C11
**근거 출처**: EARS(A) Unwanted behaviour, SK-CL(B) Exception/Recovery, YUAN(A)

## REQ-05 수용 기준

- **적용**: 공통 · **범위**: 절
- **왜 중요한가**: 수용 기준이 없으면 완료를 판정할 수 없다.
- **판정 질문**
  - 각 사용자 흐름·기능에 수용 기준이 있는가?
  - 수용 기준이 관찰 가능한 결과(상태·응답·화면·기록)로 적혔는가?

**체크포인트**
- 사용자 흐름(스토리)마다 수용 기준 목록.
- 수용 기준이 요구 본문과 같은 결과를 말하는가(다르면 CON-07).

**검사 방법**: S+L
- **스크립트 추출 대상**: 사용자 흐름 ID 목록과 각 흐름 아래 수용 기준 블록 유무.

**심각도 앵커**
- medium: 핵심 흐름에 수용 기준 없음, 또는 관찰 불가한 기준
- low: 부가 흐름에 수용 기준 없음

**근거 요구**: 흐름 인용 + 찾아본 절(부재형).

**잡는 결함 범주**: C12
**근거 출처**: SK-AN(B) C, KIRO(A)
