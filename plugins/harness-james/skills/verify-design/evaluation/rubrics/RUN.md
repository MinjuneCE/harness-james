## RUN-01 단계적 출시·되돌림

- **적용**: 공통 · **범위**: 문서
- **왜 중요한가**: 한 번에 전면 적용한 변경은 문제가 나면 되돌릴 방법이 없다.
- **판정 질문**
  - 단계적 출시 방식(범위·순서)과 변경별 되돌림 방법(플래그·설정·이전 경로 유지)이 있는가?
  - 되돌릴 수 없는 변경(DEC-03)은 그렇다고 표시됐는가?

**체크포인트**
- 기존 경로를 걷어내는 시점과 새 경로 검증의 순서.
- 되돌림 뒤 새 경로가 만든 데이터의 처리.

**검사 방법**: L

**심각도 앵커**
- high: 비가역 변경에 되돌림·단계 없음
- medium: 출시 순서·되돌림 방법 미정

**근거 요구**: 출시·전환 절 인용 또는 찾아본 곳.

**잡는 결함 범주**: C11
**근거 출처**: SRE-LAUNCH(A) rollout (refs CHG-01)

## RUN-02 데이터·계약 호환

- **적용**: data-migration · **범위**: 문서
- **왜 중요한가**: 이전 기간에는 옛/새 데이터와 계약이 공존한다. 그 동작이 정해지지 않으면 이전 중 불일치·장애가 난다.
- **판정 질문**
  - 이전 기간 동안 옛/새 데이터·계약이 공존할 때의 동작과 이전 순서가 정의됐는가?
  - 기존 레코드(새 상태·새 열이 없는 행)를 새 코드가 어떻게 다루는가가 정해졌는가?

**체크포인트**
- 이미 적용된 스키마 이전을 고치지 않고 새 이전을 더하는가.
- 제약 교체(유일성 변경) 시 기존 데이터가 새 제약을 만족하는가.
- 외부에 노출된 계약의 버전·호환.

**검사 방법**: L

**심각도 앵커**
- critical: 되돌릴 수 없는 데이터 변환에 공존·검증 계획 없음
- high: 기존 레코드가 새 제약·상태를 어기는데 처리 없음
- medium: 이전 순서 미정

**근거 요구**: 스키마·계약 변경 인용 + 공존 동작을 찾아본 곳.

**잡는 결함 범주**: C11, C04
**근거 출처**: SRE-LAUNCH(A), BEZOS(A) (refs CHG-02)

## RUN-03 자동화 안전장치

- **적용**: automation · **범위**: 문서
- **왜 중요한가**: 사람 확인 없이 대량으로 도는 작업은 한 번의 실수로 전면 장애를 낸다.
- **판정 질문**
  - 대량·자동 작업에 속도 제한, 한 번에 바꾸는 범위의 상한, 최소 보존량(지우면 안 되는 하한)이 있는가?

**체크포인트**
- 주기 작업 한 번이 바꿀 수 있는 건수.
- 외부에 비가역 부작용을 내는 자동 작업의 건수 상한.
- 사람이 멈출 수 있는 스위치.

**검사 방법**: L

**심각도 앵커**
- critical: 한 번의 오판이 대량 비가역 부작용으로 이어지고 상한 없음
- high: 대량 변경에 속도·범위 제한 없음
- medium: 멈춤 스위치 없음

**근거 요구**: 자동 작업 정의 인용.

**잡는 결함 범주**: C11
**근거 출처**: AWS-PES-2017(A), AWS-PES-2021(A) (refs CHG-03)

## RUN-04 가정 붕괴 감지

- **적용**: 공통 · **범위**: 묶음
- **왜 중요한가**: 설계 가정(외부 동작·도착 순서·처리 시간)이 깨져도 신호가 없으면 조용히 실패한다. 테스트가 가정 위반을 통과시키면(거짓 통과) 검증이 의미 없다.
- **판정 질문**
  - 핵심 가정(EVD-03 목록)마다, 깨졌을 때 알아챌 신호(막힌 상태 건수·나이·불일치 건수·테스트 실패)가 정의됐는가?
  - 그 신호가 장애 난 경로에 의존하지 않는가(같은 저장소·같은 외부 시스템이 죽으면 신호도 죽지 않는가)?
  - 검증 항목이 가정 위반 상황에서 실패하도록 설계됐는가(거짓 통과가 없는가)?

**체크포인트**
- 가정 위반이 외부에 기록을 남기지 않는 경우(관측 불가) — 그 사실이 표시됐는가.
- 지표가 0일 때 "정상"과 "관측 불가"를 구분하는가.
- 검증 환경의 구성(라이브러리 중복 로드, 스텁)이 실제와 달라 통과하는 경우.

**검사 방법**: L

**심각도 앵커**
- high: 비가역 부작용에 닿는 가정이 깨져도 알아챌 신호가 없음, 또는 핵심 검증이 거짓 통과할 수 있음
- medium: 신호가 장애 경로에 의존함, 0과 관측 불가를 구분하지 않음
- low: 부가 가정의 감지 신호 없음

**근거 요구**: 가정 인용 + 신호·검증을 찾아본 곳. 거짓 통과는 검증 기대값과 전제 인용.

**잡는 결함 범주**: C12
**근거 출처**: BL-QUEUE(A) 메시지 나이, WA-REL(A) KPI, AWS-PES-2017·2021(A) 감시 눈멂 (refs OPS-01·02 흡수)
